# 예외처리 가이드 v0.1

현재 코드와 `nail_msgs` 계약 기준의 예외처리 지침이다.

## 1. 안전 입력

실제 안전 입력은 E-Stop과 두산 컨트롤러 통신 상태다. F/T, 손 안착, 더스트
센서는 장비와 소프트웨어 계약에 없다.

| 결함 | 조건 | 복구 |
|---|---|---|
| `FAULT_ESTOP` | DSR 상태 6 또는 7 | E-Stop 해제 후 `ResetSafety(confirm=true)` |
| `FAULT_COMM_LOST` | 컨트롤러 상태 조회 실패 또는 타임아웃 | 통신 복구 후 `ResetSafety(confirm=true)` |

결함은 래치된다. `auto_reset=false`를 유지하며, 원인이 남아 있으면 reset은
`remaining_faults`를 반환하고 실패해야 한다.

## 2. 표준 에러 처리

| 코드 | 대표 원인 | 처리 |
|---|---|---|
| `E_INVALID_GOAL` | 필수값 누락, 무효 경계, 기하 한계 위반 | 이동 전 REJECT 또는 실행 전 ABORT |
| `E_SAFETY_BLOCKED` | `safe_to_move=false` 또는 안전 상태 만료 | 새 goal 거부, 실행 중 중단 |
| `E_PRECOND_FAILED` | `/safety/validate` 실패 | 이동 전 거부 |
| `E_TIMEOUT` | 액션·드라이버·하위 응답 지연 | 하위 취소 후 이탈 |
| `E_CANCELLED` | 사용자 또는 상위 취소 | 하위 취소 전파 후 이탈 |
| `E_COMM_LOST` | 컨트롤러나 하위 서버 연결 실패 | 세션 중단 |
| `E_MOTION_FAILED` | TF, 도달성, DSR 명령, 최종 자세 검증 실패 | 정지 후 이탈 |
| `E_LATERAL_LIMIT` | 수평 경로의 기하 경계 위반용 계약 상수 | 현재 구현은 실행 전 `E_INVALID_GOAL`로 차단하므로 발행하지 않음 |
| `E_TOOL_MISMATCH` | 요구 툴 불일치 | goal 거부 |
| `E_GRIP_FAILED` | 그리퍼 서비스 명령 실패 | 현재 툴을 `none`으로 처리하고 중단 |

## 3. 경로 안전

- `ContactPath`는 `allowed_polygon` 밖 waypoint를 발견하면 이동하지 않고
  즉시 중단한다. 종료 시 작업면에서 이탈한다.
- `LateralContact`는 티칭 waypoint만 따라가며 종료 시 `approach_vector`의
  반대 방향으로 후퇴한다.
- `sanding_node`는 티칭 경계로 이동 가능 거리를 계산하고, 설정된 진입 깊이가
  한계를 넘으면 로봇을 움직이기 전에 거부한다.
- 실행 중에는 `/safety/status`, 취소, 타임아웃, DSR 결과와 최종 자세 오차를
  감시한다.
- 티칭 좌표가 실제 작업물과 일치하는지는 운영자가 더미에서 먼저 확인한다.

## 4. 그리퍼와 툴

`PickPlace` 성공은 이동과 그리퍼 명령 성공만 뜻한다. 실제 파지 폭이나 물체
보유 상태를 읽지 않으므로 파지, 반납, 스톤 부착은 육안으로 확인한다.

- 그리퍼 명령 실패: `E_GRIP_FAILED`
- 랙 이동 전 중립 TCP 전환 실패: `E_MOTION_FAILED`
- 툴 반납 실패: 현재 보유 상태를 숨기지 않고 중단
- UV 반납 실패: HOME 복귀 금지, 정지 후 수동 개입 요청

## 5. 취소와 세션 정리

```text
RunSession cancel
  -> 현재 공정 action cancel
  -> 현재 skill action cancel
  -> DSR 정지 확인
  -> 경로 이탈
  -> 가능하면 툴 반납
  -> 안전한 경우에만 HOME 복귀
```

각 계층은 자신이 보낸 하위 goal handle을 보관해야 한다. 타임아웃도 같은 취소
경로를 사용한다.

## 6. 운용 파라미터

- `safety_monitor.publish_rate_hz=3`
- `safety_monitor.heartbeat_timeout_ms=3000`
- 소비 노드의 `safety_status_timeout_s=1.0`
- `safety_monitor.auto_reset=false`

발행 주기와 소비 타임아웃을 따로 변경하면 정상 통신을 안전 차단으로 오판할 수
있으므로 함께 검토한다.
