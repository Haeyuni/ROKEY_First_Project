# 노드별 단위 테스트 가이드

**문서 ID** UTG-NAIL-v0.3 · **상위 문서** NIS-NAIL-v0.3 · **개정일** 2026-08-26

현재 M0609 + RG2 장비와 `nail_msgs` 계약을 사람이 단계별로 확인하는 절차다.
별도 자동 테스트 코드 추가를 전제로 하지 않는다.

## 0. 전체 통합 테스트

테스트 컴퓨터에서 두산 M0609/RG2 드라이버를 먼저 켠 뒤, 아래 명령을 실행한다.

```bash
source /opt/ros/jazzy/setup.bash && source ~/ws_cobot_pjt/ws_dsr/install/setup.bash && source ~/ws_cobot_pjt/ws_cobot1/install/setup.bash && ros2 launch nail_bringup integration_bringup.launch.py
```

## 1. 준비

각 터미널에서 다음 환경을 적용한다.

```bash
source /opt/ros/<distro>/setup.bash
source ~/ws_cobot_pjt/ws_dsr/install/setup.bash
source ~/ws_cobot_pjt/ws_cobot1/install/setup.bash
```

인터페이스가 바뀌었으므로 최소한 관련 패키지를 빌드한다.

```bash
colcon build --packages-select nail_msgs nail_perception nail_skill nail_process nail_orchestrator nail_safety nail_bringup
source install/setup.bash
```

설정 파일을 수정한 뒤에는 재빌드와 노드 재시작이 필요하다. 모든 실제 동작은
낮은 속도로 더미에서 먼저 실행하고, 운영자가 로봇 옆에서 E-Stop을 사용할 수
있어야 한다.

### 3.1 `MoveTo`

안전한 빈 공간의 좌표로 먼저 확인한다.

```bash
ros2 action send_goal /skill/move_to nail_msgs/action/MoveTo "{
  target: {position: {x: 0.4, y: 0.0, z: 0.3},
           orientation: {x: 0.0, y: 1.0, z: 0.0, w: 0.0}},

}" --feedback
```

| 확인 | 기대 결과 |
|---|---|
| 정상 좌표 | `base.success=true`, 최종 위치 오차가 허용값 이내 |
| E-Stop 상태 | goal 거부, 로봇 무동작 |
| 도달 불가 좌표 | `E_MOTION_FAILED` |
| 짧은 `timeout_s` | `E_TIMEOUT` 또는 `E_MOTION_FAILED` |

### 3.2 `PickPlace`

```bash
ros2 action send_goal /skill/pick_place nail_msgs/action/PickPlace "{
  mode: 'pick', target_key: 'sander', frame_id: 'base_link',
  approach_height_mm: 20.0, grip_width_mm: 20.0,
  already_holding: false

```

육안으로 상공 이동, 개방, 하강, 닫기 명령, 상승을 순서대로 확인한다. result에
실제 파지 측정값은 없다. `base.success=true`여도 툴이 실제로 잡혔는지 반드시
눈으로 확인한다.

반납:

```bash
ros2 action send_goal /skill/pick_place nail_msgs/action/PickPlace "{
  mode: 'place', target_key: 'sander', frame_id: 'base_link',
  approach_height_mm: 20.0, grip_width_mm: 0.0,
  already_holding: false
}" --feedback
```

| 확인 | 기대 결과 |
|---|---|
| 잘못된 `mode` | goal 거부, 로봇 무동작 |
| 빈 `target_key` | goal 거부, 로봇 무동작 |
| 그리퍼 서비스 실패 | `E_GRIP_FAILED` |
| 이동 중 취소 | `CANCELED`, 안전 상승 또는 이탈 |

#### 3.2.1 나사 뚜껑 열고 닫기 (`unscrew`)

코터는 젤 병에 나사로 잠긴 뚜껑이 곧 붓이다. `unscrew: true` 인 툴은 슬롯에서
대칭으로 여닫는다.

```
PICK   슬롯 100mm 위 → 손목 감기(J6 +) → 하강 → 최소폭 파지 → 풀기 회전(+상승)
       → 젤 훑기 → 수직 이탈 → 손목 되감기
PLACE  슬롯 100mm 위 → 손목 감기(J6 +) → 하강(나사 여유만큼 띄워서) → 잠금 회전(+하강)
       → 개방 → 수직 이탈 → 손목 되감기
```

**손목 감기**가 핵심이다. 이게 없으면 실제로 돌 수 있는 각도가 슬롯 자세를
티칭할 때 우연히 정해진 J6 시작각에 좌우된다(같은 코드가 두 바퀴를 돌기도,
5°만 돌고 말기도 한다). 돌리기 전에 손목을 **J6 + 쪽으로** 필요한 만큼 미리
감아 두므로 티칭 시 J6 를 맞출 필요가 없다. 감는 방향은
`unscrew_prewind_j6_sign`(기본 +1)이며, 5° 탐색 회전으로 실측한 방향이 이 값과
어긋나면 경고가 뜬다 — 그건 `unscrew_total_deg` 의 부호가 반대(= 조이는 방향)
라는 신호다.

**젤 훑기**는 뚜껑(=붓)을 뽑기 직전에 붓에 묻은 젤 여분을 병 입구에 닦아내는
단계다. 슬롯 파지 z 에서 `unscrew_wipe_lift_mm`(기본 30mm) 올라간 높이에서
슬롯 XY 기준 앞(+X) → 뒤(-X) 를 `unscrew_wipe_cycles`(기본 3)회 왕복하고
가운데로 돌아온다. `unscrew_wipe_lift_mm: 0` 으로 두면 이 단계를 건너뛴다.

**⚠️ 손목 감기는 슬롯 100mm 위(`unscrew_prewind_height_mm`)에서 그리퍼를 벌린
채 최대 두 바퀴 가까이 회전한다. 첫 실행 전에 그 높이에서 옆 슬롯·구조물과
간섭이 없는지 반드시 눈으로 확인할 것.**

**⚠️ 첫 시험은 젤 병을 슬롯에서 빼고 빈 슬롯 또는 여분 뚜껑으로 한다.**
회전 방향(부호)이 틀리면 뚜껑을 더 조인다.

1) 간섭부터 확인 — 회전 없이 손목 감기 높이만 확인한다.

```bash
ros2 param set /robot_skill_node unscrew_total_deg -20.0
ros2 param set /robot_skill_node unscrew_speed_degs 15.0
```

2) 방향 확인 — 90°만 돌려 보고 푸는 방향인지 눈으로 본다.

```bash
ros2 param set /robot_skill_node unscrew_total_deg -90.0

ros2 action send_goal /skill/pick_place nail_msgs/action/PickPlace "{
  mode: 'pick', target_key: 'coater', frame_id: 'base_link',
  approach_height_mm: 20.0, grip_width_mm: 16.0,
  unscrew: true, unscrew_grip_width_mm: 0.0
}" --feedback
```

반대로 돌면 `unscrew_total_deg` 를 `+90.0` 으로 뒤집는다. 방향이 맞으면
`-360 → -540`(기본값) 순으로 늘리고 속도를 기본값(45°/s)으로 되돌린다.

**`unscrew_total_deg` 의 절댓값은 690 을 넘길 수 없다** — 손목을 반대쪽 끝까지
감아도 `(J6 한계 360 − 여유 15) × 2 = 690°` 가 이론 최대다. 그 이상을 넣으면
항상 690° 에서 잘리고 `J6 가동범위 소진` 경고가 뜬다.

3) 나사 피치 확인 — 돌면서 뚜껑을 축방향으로 잡아당기거나 누르지 않는지 본다.
어긋나면 `unscrew_lift_per_turn_mm` 를 실제 피치에 맞춘다.

4) 젤 훑기 높이 맞추기 — 먼저 훑기를 끄고 뚜껑 풀기만 확인한 뒤 켠다.

```bash
ros2 param set /robot_skill_node unscrew_wipe_lift_mm 0.0    # 끄기
# 뚜껑 풀기가 정상이면 켠다
ros2 param set /robot_skill_node unscrew_wipe_lift_mm 30.0
ros2 param set /robot_skill_node unscrew_wipe_x_mm 5.0
ros2 param set /robot_skill_node unscrew_wipe_cycles 3
```

붓이 병 입구에 **살짝 닿아 훑기는 하되 걸리지는 않는** 높이를 찾는다. 너무
낮으면 붓이 병목에 끼고, 너무 높으면 허공에서 흔들 뿐 젤이 안 떨어진다.
`unscrew_wipe_x_mm` 는 병 입구 반지름보다 작게 둔다 — 크면 붓이 입구 턱을
넘어가 밖으로 젤을 흘린다.

5) 닫기 확인 — 같은 파라미터로 PLACE 를 보낸다. 뚜껑이 병에 잠긴 채 남아야
한다. 과조임이 나면 `unscrew_close_deg` 를 열기 각도보다 작게 준다(기본 0 =
`-unscrew_total_deg`, 즉 푼 만큼 그대로 되감기).

```bash
ros2 action send_goal /skill/pick_place nail_msgs/action/PickPlace "{
  mode: 'place', target_key: 'coater', frame_id: 'base_link',
  approach_height_mm: 20.0, grip_width_mm: 0.0,
  unscrew: true, unscrew_grip_width_mm: 0.0
}" --feedback
```

| 확인 | 기대 결과 |
|---|---|
| PICK 정상 | 손목 감기 → 파지 → 풀기 → 젤 훑기 → 이탈 → 되감기. `unscrew_done_deg` = `unscrew_total_deg` |
| 젤 훑기 | 슬롯 z+30mm 에서 X 로 3회 왕복 후 가운데 복귀. 붓 여분 젤이 병 안으로 떨어진다 |
| 감기 방향 경고 | `손목 감기 방향이 설정과 반대` 가 뜨면 `unscrew_total_deg` 부호를 의심한다 |
| PLACE 정상 | 손목 감기 → 하강 → 잠금 → 개방 → 이탈 → 되감기. 뚜껑이 병에 잠긴 채 남는다 |
| 되감기 후 자세 | 이탈 완료 시 J6 가 시작값 ±5° 이내로 복귀 (다음 이동이 손목을 한 바퀴 휘두르지 않음) |
| 목표가 690° 초과 | 690° 에서 잘림 + `J6 가동범위 소진` 경고, `success=true` |
| 회전 중 취소 | `CANCELED`, 그 구간에서 정지 |
| `unscrew: false`(기존 툴) | 회전·감기 없음, `unscrew_done_deg=0`, 기존과 동일 |
| 뚜껑이 안 잡혀 헛돎 | `J6 가 … 만 움직였습니다` 경고 후 회전 중단 |

전체 툴 교체로 확인 (반납 때 닫고, 파지 때 여는 것을 한 번에 본다):

```bash
ros2 action send_goal /tool/change nail_msgs/action/ChangeTool "{
  target_tool: 'coater', park_facing: 'into_rack'
}" --feedback

ros2 topic echo /tool/status --once   # grip_width_mm 가 unscrew_grip_width_mm 값
```

### 3.3 `ContactPath`

`taught_surfaces.yaml`의 브러시 또는 코터 여섯 Pose를 실측 입력하되 처음에는
`configured=false`를 유지한다. 좌표와 자세를 검토한 뒤 `contact_offset_mm`을
충분한 음수로 두어 공중 경로부터 확인하고, 그때만 해당 항목을 true로 바꾼다.
임의의 예제 절대좌표를 실제 로봇에 보내지 않는다.

| 확인 | 기대 결과 |
|---|---|
| 정상 | 절대 Pose 곡면을 `MoveC`/`MoveL`로 순회, `passes_done=1`, 종료 후 이탈 |
| 빈 waypoint | goal 거부 |
| 미설정 6-Pose | 공정 goal 거부, 로봇 무동작 |
| 잘못된 원호 인덱스 | goal 거부, 로봇 무동작 |
| 다각형 밖 waypoint | 해당 점으로 이동하지 않고 경로 중단 |
| 취소·타임아웃 | 하위 이동 정지 후 이탈 |

공중 경로가 정상이고 후퇴 방향이 맞는 것을 확인한 뒤에만
`contact_offset_mm`을 `-20 → -10 → -5 → 0 mm` 순서로 줄인다. 0 mm는
티칭한 접촉점 그대로이며, 실제 접촉 여부는 육안으로 확인한다.

### 3.5 독립 Probe 경계 탐색

Probe는 전체 통합 launch나 orchestrator에 포함되지 않는다. 운영자가 Probe를
장착하고 티칭 좌표·누르는 축·E-Stop을 다시 확인한 뒤 아래 조합만 별도로 띄운다.

```bash
ros2 launch nail_bringup test_bringup.launch.py nodes:=safety,skill,probe
```

먼저 한 점만 실행한다. 아래 Pose는 2026-08-26 center 비교 시험값일 뿐이며,
Probe TCP를 등록한 뒤에는 그대로 재사용하지 말고 다시 티칭해야 한다.

```bash
ros2 action send_goal /skill/probe_point nail_msgs/action/ProbePoint "{
  search_start: {
    position: {x: 0.37754, y: -0.01866, z: 0.44637},
    orientation: {x: 0.029225, y: 0.999400, z: -0.013477, w: -0.012800}},
  press_direction: {x: -0.0264, y: -0.0262, z: -0.9993},
  frame_id: 'base_link', source: 'manual',
   air_offset_z_mm: 60.0, max_depth_mm: 10.0, probe_speed_mms: 0.7,
   comparison_margin_n: 0.3, max_force_n: 5.0,
   lateral_force_limit_n: 4.0, confirm_samples: 3, stiffness_depth_mm: 0.5,
   timeout_s: 40.0,
   manual_probe_tool_confirmed: true
}" --feedback
```

한 점 결과의 `stiffness_n_per_mm`을 확인한다. 손톱 내부와 더미손 표면에서 각각
3회 이상 실행했을 때 강성값 범위가 겹치면 경계 스캔을 실행하지 않는다.

경계 스캔 전에는 다음 Pose를 새 Probe 장착 상태에서 티칭한다. 모두 동일한 Probe
자세를 쓰고, `max_depth_mm` 안에서 손톱과 더미손 표면에 닿는 공중 시작 높이여야 한다.

```text
scan_corners[0] = top_left       # 탐색 사각형 공중 모서리
scan_corners[1] = top_right
scan_corners[2] = bottom_right
scan_corners[3] = bottom_left
nail_reference  = 손톱 내부가 확실한 공중 시작 Pose
dummy_references = 손톱 밖 더미손 공중 시작 Pose 1개 이상 (권장: 좌/우/앞/뒤 4개)
```

사각형은 손톱과 주변 더미손을 모두 포함하되, 네 모서리와 모든 격자점이 실제로
도달 가능해야 한다. `ScanBoundary`는 기준점의 강성 중앙값을 먼저 비교한 뒤, 손톱
기준점에 연결된 재질 후보만 남긴다. `E_NO_BOUNDARY`가 나오면 기준점 강성 차이,
사각형 범위, 시작 높이 또는 `material_min_separation_n_per_mm`을 확인한다.

## 4. `tool_manager`

`PickPlace`를 먼저 확인한 뒤 실행한다.

```bash
ros2 action send_goal /tool/change nail_msgs/action/ChangeTool "{
  target_tool: 'sander', park_facing: 'into_rack'
}" --feedback

ros2 topic echo /tool/status --once
ros2 service call /tool/get_info nail_msgs/srv/GetToolInfo "{tool_id: ''}"
```

확인 항목:

- 랙 이동 전에 중립 TCP로 전환한다.
- 새 툴을 집은 뒤 `active_tcp='tcp_sander'`가 된다.
- `grip_width_mm`는 명령값으로만 해석한다.
- 실제 툴 파지는 육안으로 확인한다.
- 연속 교체에서 이전 툴 반납이 먼저 실행된다.
- 취소가 하위 `PickPlace`로 전파된다.
- UV 반납 실패 시 HOME으로 이동하지 않는다.

## 5. `safety_monitor`

```bash
ros2 topic hz /safety/status
ros2 service call /safety/validate nail_msgs/srv/ValidatePrecondition \
  "{stage: 'SAND', session_id: 'manual_check', required_tool: 'sander'}"
```

| 확인 | 기대 결과 |
|---|---|
| 요구 툴 불일치 | `ok=false`, 사유 배열에 툴 불일치 |
| E-Stop 누름 | `FAULT_ESTOP`, `safe_to_move=false` |
| E-Stop 해제 전 reset | 결함 유지 |
| 컨트롤러 통신 끊김 | `FAULT_COMM_LOST`, `comm_ok=false` |
| `auto_reset` | 운용값 `false` |

## 6. 티칭 경계 확인

`nail_perception`은 설정값만 계산하므로 이 절차가 모든 공정의 전제다.

```bash
ros2 run tf2_ros tf2_echo base_link nail_local_frame
ros2 param get /sanding_node nail_size_x_mm
ros2 param get /sanding_node nail_size_y_mm
ros2 param get /sanding_node nail_boundary_points
```

툴을 제거하거나 충분히 이격한 상태에서 `MoveTo`로 손톱 중심 5 mm 위를 낮은
속도로 확인한다. 지그 위치, 손톱 중심, 높이 또는 축이 다르면 공정을 실행하지
말고 `static_frames.yaml`을 다시 티칭한다.

## 7. 공정 노드

### 7.1 연마

```bash
ros2 action send_goal /process/sand nail_msgs/action/SandSurface "{
  session_id: 'manual_check', approach_side: 'free_edge',
  approach_pitch_deg: 0.0, work_plane_offset_mm: 0.0,
  passes: 1, step_over_mm: 1.5, feed_speed_mms: 3.0,
  max_duration_s: 30.0, travel_limit_margin_mm: 2.0
}" --feedback
```

- `computed_travel_limit_mm > 0`인지 확인한다.
- `max_travel_mm`과 `travel_mm`은 설정된 기하 진입 깊이와 일치해야 한다.
- 무효 경계나 한계보다 큰 `engagement_depth_mm`은 이동 전에 실패해야 한다.
- 성공·취소·실패 뒤 역방향 후퇴를 육안으로 확인한다.

### 7.2 브러싱

```bash
ros2 action send_goal /process/brush nail_msgs/action/BrushDust "{
  session_id: 'manual_check', passes: 1, path_pitch_mm: 2.0,
  feed_speed_mms: 10.0, coverage_margin_mm: 0.0,
  max_duration_s: 20.0
}" --feedback
```

티칭 경계 안의 경로 완료와 종료 후 이탈을 확인한다. 성공은 경로 완료만 뜻한다.

### 7.3 도포

```bash
ros2 action send_goal /process/coat nail_msgs/action/CoatGel "{
  session_id: 'manual_check', layer_index: 0,
  boundary_offset_mm: 1.0, path_pitch_mm: 1.5,
  feed_speed_mms: 10.0, passes: 1, max_duration_s: 30.0
}" --feedback
```

`boundary_offset_mm` 증가 시 경로가 안쪽으로 줄어드는지 확인한다.
`coverage_ratio`는 경로 계산값으로만 해석한다.

### 7.4 UV 경화

UV 차폐, 보호구, 수동 전원 차단과 안전한 랙 방향을 먼저 확인한다.

```bash
ros2 action send_goal /process/cure nail_msgs/action/CureUV "{
  session_id: 'manual_check', layer_index: 0,
  standoff_mm: 15.0, standoff_tolerance_mm: 3.0,
  dwell_points: 2, dwell_s_per_point: 2.0,
  path_speed_mms: 3.0, park_distance_mm: 120.0,
  max_duration_s: 30.0
}" --feedback
```

완료 시 `parked=true`를 확인한다. 취소나 안전 차단에서도 조사 영역 밖으로
물리적으로 이탈해야 한다.

### 7.5 스톤

```bash
ros2 action send_goal /process/place_stone nail_msgs/action/PlaceStone "{
  session_id: 'manual_check',
  target_position: {x: 0.0, y: 0.0, z: 0.0},
  target_yaw_deg: 0.0, press_duration_s: 1.0,
  approach_height_mm: 15.0
}" --feedback
```

`actual_position`은 명령값이다. 스톤 픽업과 부착은 육안으로 확인한다.

## 8. 세션 통합 확인

개별 절차를 완료한 뒤에만 실행한다.

```bash
ros2 action send_goal /session/run nail_msgs/action/RunSession "{
  session_id: 'manual_session', recipe_id: 'default',
  shape_profile_id: 'default', target_material: 'artificial_tip',
  layer_total: 1, enable_brush: true, enable_stone: false
}" --feedback
```

별도 터미널에서 확인한다.

```bash
ros2 topic echo /process/status
```

기대 순서는 `PRECHECK -> SAND -> BRUSH -> COAT -> CURE -> FINISH`다.
취소 시 현재 공정과 스킬로 취소가 전파되고, 이탈과 가능한 툴 반납 후 안전한
경우에만 HOME으로 복귀해야 한다.

## 9. 완료 체크리스트

- [ ] 모든 goal 예제가 현재 `ros2 interface show` 필드와 일치한다.
- [ ] `/safety/status` 만료 또는 `safe_to_move=false`에서 이동하지 않는다.
- [ ] 취소와 타임아웃이 하위 action까지 전파된다.
- [ ] `ContactPath`의 경계 밖 waypoint가 실행되지 않는다.
- [ ] `LateralContact` 종료 후 역방향 후퇴한다.
- [ ] 연마 진입 깊이가 티칭 경계 한계를 넘지 않는다.
- [ ] TCP와 `/tool/status.active_tcp`가 일치한다.
- [ ] 파지와 부착 성공을 result가 아닌 육안으로 확인했다.
- [ ] UV 중단과 반납 실패 시 안전한 물리 이탈 정책을 지킨다.
