## 1. 읽는 법

각 노드는 아래 **8개 항목**으로 동일하게 기술됩니다.

| 항목 | 뜻 |
|---|---|
| **역할** | 이 노드가 존재하는 이유 한 줄 |
| **제공 (서버)** | 다른 노드가 이 노드를 호출할 때 쓰는 인터페이스 |
| **소비 (클라이언트)** | 이 노드가 다른 노드를 호출할 때 쓰는 인터페이스 |
| **파라미터** | `declare_parameter`로 선언할 설정값 ← **v0.2 신설** |
| **동작** | 요청을 받고 나서 하는 일의 순서 |
| **반환값** | result 필드 각각의 의미와, 호출자가 그걸로 뭘 판단하는지 |
| **피드백** | 실행 중 흘려보내는 정보와 주기 |
| **주요 에러** | 실패 코드, 원인, 처리 방식 |

### 표기 규칙

| 표기 | 뜻 |
|---|---|
| `Action` | 오래 걸리고 취소 가능. goal → feedback → result |
| `Service` | 즉답 (목표 응답 5 ms 이내). 블로킹 호출 금지, 반드시 async |
| `Topic(pub)` | 이 노드가 발행 |
| `Topic(sub)` | 이 노드가 구독 |
| `TF` | 좌표 변환 브로드캐스트/조회 |
| ★ | 실패 시 프로젝트 전체가 막히는 지점 |

파라미터 표의 **`캘`** 표시는 실측 캘리브레이션으로 확정해야 하는 값입니다. 착수 시점에는 표의 값을 임시로 쓰되, C-01/C-02 실험 결과로 반드시 덮어씁니다.

> **⚠️ 서비스 호출 주의**
> ROS2에서 콜백 안에서 서비스를 동기 호출하면 **데드락**이 납니다. 액션 서버의 `goal_callback` 안에서 `ValidatePrecondition`을 부르는 코드가 전 노드에 반복해서 나오므로, **반드시 `MutuallyExclusiveCallbackGroup`을 분리하거나 async 호출**을 쓰세요. 이 프로젝트에서 가장 나오기 쉬운 버그입니다.

## 3. 모든 노드가 지켜야 할 공통 규약

**이 장의 규약을 어기는 코드는 리뷰에서 반려합니다.** 12개 노드가 제각각 동작하면 통합이 불가능해집니다.

### 3.1 액션 서버 표준 수명주기

```
① goal 수신
      ↓
② 파라미터 유효성 검사        → 실패 시 REJECT (E_INVALID_GOAL)
      ↓
③ /safety/status.safe_to_move 확인 → false면 REJECT (E_SAFETY_BLOCKED)
      ↓
④ ValidatePrecondition 호출   → ok=false면 REJECT (E_PRECOND_FAILED)
      ↓
⑤ ACCEPT → 실행 시작
      ↓
⑥ 실행 중 매 주기:
      · feedback 발행
      · is_cancel_requested 확인   → true면 안전 정지 → CANCELED
      · safe_to_move 재확인        → false면 즉시 정지 → ABORT
      ↓
⑦ 종료 처리 (성공/실패/취소 공통):
      · 툴을 표면에서 이탈시킨다
      · 필요 시 HOME 복귀
      · result 채워서 반환
```

> **③④를 goal 수락 전에 하는 이유**: 이미 수락한 goal을 도중에 죽이는 것보다, 애초에 받지 않는 편이 로봇이 움직이지 않아 안전하고 로그도 깔끔합니다.

### 3.2 REJECT vs ABORT 구분

| | 언제 | 로봇 상태 |
|---|---|---|
| **REJECT** | goal을 **받기 전** 판단. 전제조건 미충족 | **한 번도 안 움직임** |
| **ABORT** | goal을 받고 **실행 중** 실패 | 움직이던 중 정지 → 이탈 → HOME |
| **CANCEL** | 외부에서 취소 요청 | 정지 → 이탈 → HOME |

`ABORT`와 `CANCEL`은 뒷정리(이탈 + HOME)가 **완전히 같습니다.** 공통 함수 하나로 구현하세요.

**단, 이탈 방향은 접근 방향에 따라 다릅니다.** `ContactPath`/`ProbePoint`는 표면 법선(+Z) 이탈, `LateralContact`는 접근 벡터 역방향 이탈입니다. §5.1 참조.

### 3.3 취소 전파 규칙

```
RunSession cancel
   → 진행 중인 공정 액션(예: SandSurface) cancel
      → 진행 중인 스킬 액션(LateralContact) cancel
         → dsr 정지 명령
```

**공정 노드는 자기가 호출한 스킬 액션의 goal_handle을 반드시 멤버로 보관**해야 합니다.

### 3.4 안전 상태 구독 의무

**모든 노드는 `/safety/status`를 구독합니다.** 예외 없습니다. `safe_to_move == false`가 관측되면:

- 액션 서버는 실행 중인 goal을 `ABORT(E_SAFETY_BLOCKED)`
- 새 goal은 `REJECT`
- `curing_node`는 추가로 **즉시 조사 영역 밖으로 이탈** (v0.2: permit 반납이 아니라 물리적 회피)

### 3.5 로깅 규칙

| 레벨 | 쓰는 경우 |
|---|---|
| `DEBUG` | 매 주기 힘 값 등 대량 데이터 |
| `INFO` | goal 수락/완료, 상태 전이 |
| `WARN` | 재시도, 임계값 근접 |
| `ERROR` | ABORT, 통신 실패, 안전 결함 |

모든 ABORT 로그는 **에러 코드 문자열을 반드시 포함**합니다: `[E_LOW_STIFFNESS] sanding aborted at (12.3, 4.5)`

### 3.6 파라미터 선언

모든 노드는 시작 시 `declare_parameter`로 설정을 선언하고, 하드코딩 상수를 두지 않습니다.

```python
self.declare_parameter('max_force_n', 5.0)
self.declare_parameter('use_mock_hardware', False)
```

**전 노드 공통 파라미터 (예외 없음)**

| 이름 | 타입 | 기본 | 설명 |
|---|---|---|---|
| `use_mock_hardware` | bool | `false` | Phase 0 mock 개발 전제 |
| `node_timeout_s` | double | `120.0` | 액션 자체 타임아웃 |
| `safety_topic` | string | `/safety/status` | 안전 토픽 경로 |
| `log_force_data` | bool | `false` | DEBUG 힘 로그 on/off |

파라미터 파일은 `config/<node_name>.yaml` 하나씩 두고, launch에서 주입합니다. **런치 인자 하나(`use_mock_hardware:=true`)로 전 노드가 mock으로 전환**되어야 합니다.

## 4. 공통 에러 코드

`result.error` 필드에 아래 문자열을 그대로 넣습니다. 자유 서술 금지 — 웹에서 파싱해 사용자 메시지로 바꿔야 합니다.

| 코드 | 의미 | 주 발생 노드 | 결과 |
|---|---|---|---|
| `E_INVALID_GOAL` | 파라미터 범위 위반 | 전체 | REJECT |
| `E_SAFETY_BLOCKED` | `safe_to_move == false` | 전체 | REJECT / ABORT |
| `E_PRECOND_FAILED` | 전제조건 검사 실패 | 공정 노드 | REJECT |
| `E_NO_SCAN` ★ | 강성 맵 없음 또는 `valid=false` | sanding, coating, curing | REJECT |
| `E_TOOL_MISMATCH` | 요구 툴 ≠ 장착 툴 | 공정 노드 | REJECT |
| `E_GRIP_FAILED` | 파지 폭 검증 실패 | robot_skill, tool_manager | ABORT |
| `E_TOOL_DROP` | 이동 중 파지 상실 | robot_skill | ABORT + 안전 정지 |
| `E_NO_CONTACT` | 탐색 깊이 내 표면 미검출 | robot_skill, scan | ABORT |
| `E_OVERFORCE` | `max_force_n` 초과 | robot_skill | ABORT + 즉시 후퇴 |
| `E_LOW_STIFFNESS` ★ | 강성 하한 미만 = **피부 접촉 의심** | robot_skill | ABORT + 즉시 후퇴 |
| **`E_LATERAL_LIMIT`** ★ | 수평 이동 한계 초과 = **손가락 방향 진행** | robot_skill (Lateral) | ABORT + 즉시 후퇴 |
| **`E_LATERAL_JAM`** | 수평 저항 급증 = 모서리 걸림 | robot_skill (Lateral) | ABORT + 후퇴 |
| `E_MOTION_FAILED` | 드라이버 실패 (특이점·한계·서비스 오류) | robot_skill | ABORT |
| `E_COMM_LOST` | 하트비트 타임아웃 | safety_monitor | 전체 ABORT |
| `E_TIMEOUT` | 액션 자체 타임아웃 | 전체 | ABORT |
| `E_CANCELLED` | 사용자/상위 취소 | 전체 | CANCELED |
| `E_REWORK_EXCEEDED` | 재작업 한도 초과 | orchestrator | ABORT |
| `E_STONE_MISS` | 스톤 위치 오차 한도 초과 (재시도 소진) | stone | ABORT |
| `E_SEPARATION_LOW` ★ | 강성 분리도 부족 = **경계 판별 불가** | scan | ABORT |
| **`E_COARSE_INSUFFICIENT`** | 거친 스캔 유효점 부족 → 군집화 불가 | scan | ABORT |

**v0.2에서 삭제된 코드**: `E_UV_DENIED`, `E_UV_TIMEOUT` (permit 폐지)

> **★ 네 개가 이 프로젝트의 성패를 가릅니다.**
> `E_SEPARATION_LOW`는 스캔이 실패했다는 뜻이고, `E_NO_SCAN`은 그 결과로 후속 공정이 전부 막힌다는 뜻이며, `E_LOW_STIFFNESS`와 `E_LATERAL_LIMIT`은 **피부를 갈 뻔했다**는 뜻입니다. 이 넷은 **로그에 반드시 좌표와 측정값을 함께 남기세요.**

#### 동작

**`MoveTo`**
```
1. target을 base_0 기준으로 TF 변환
2. linear=true면 movel, false면 movej 호출
3. 완료 대기 (드라이버 응답 + 자세 오차 확인)
```

**`PickPlace`** — P01~P13을 전부 대체
```
PICK :  targets.yaml에서 target_key 조회
        → 접근 높이로 이동 → 하강 → 그리퍼 Close
        → verify_grip이면 폭 피드백 확인 → 상승
PLACE:  접근 높이로 이동 → 하강 → 그리퍼 Open → 상승
```

**`ContactPath`** — M02/M03 (브러싱·도포)
```
1. 시작점 위 접근 높이로 이동
2. 표면 탐색: contact_search_speed_mms로 하강하며 접촉 감지
   → contact_search_max_depth_mm 내 미검출이면 E_NO_CONTACT
3. target_force까지 천천히 접촉
4. use_compliance면 순응제어 활성화
5. waypoints 순회. 매 주기(20 Hz):
     · |F| > max_force_n            → +Z 후퇴 + E_OVERFORCE
     · k < min_stiffness (옵션 on)  → +Z 후퇴 + E_LOW_STIFFNESS
     · 취소/안전 확인
6. 순응제어 해제 → +Z 이탈
```

**`LateralContact`** ← **v0.2 신설, M01 전용**
```
0. goal 필수 필드
     approach_vector   : nail_local_frame 기준 접근 방향 단위벡터 (수평)
     work_plane_z_mm   : 작업 평면 높이 (표면에서 띄울 값)
     waypoints         : 접근 벡터에 수직인 평면 내 경로
     target_force_n    : 접근 벡터 방향으로 유지할 접촉력
     travel_limit_mm   : 접근 벡터 방향 최대 진행 거리 ★

1. 안전 대기점 → work_plane_z_mm 높이로 수평 이동
2. 수평 탐색: approach_vector 방향으로 lateral_search_speed_mms 전진
     · 접촉 감지 = approach_vector 성분 힘 > lateral_contact_threshold_n
     · travel_limit_mm 초과해도 미접촉 → 즉시 후퇴 + E_LATERAL_LIMIT ★
3. target_force_n까지 전진
4. 순응제어: approach_vector 축만 힘 제어, 나머지는 위치 제어
5. waypoints 순회 (접근축에 수직인 평면 내 이동). 매 주기(20 Hz):
     · 접근축 힘 > max_force_n           → 후퇴 + E_OVERFORCE
     · 접근축 누적 진행 > travel_limit_mm → 후퇴 + E_LATERAL_LIMIT ★
     · 진행축 저항 > lateral_jam_force_n → 후퇴 + E_LATERAL_JAM
     · 취소/안전 확인
6. 순응제어 해제 → approach_vector 역방향으로 lateral_retreat_mm 후퇴
```

> **⚠️ `ContactPath`와 `LateralContact`를 하나로 합치지 마세요.**
> 겉보기엔 "힘 유지하며 경로 추종"으로 같아 보이지만, 안전 감시 논리가 다릅니다.
>
> - **법선 접근(`ContactPath`)**: 압입 강성 `ΔF/Δz`를 계속 측정할 수 있어, 강성이 떨어지면 "피부에 닿았다"고 판정 가능
> - **수평 접근(`LateralContact`)**: 접근축으로 밀고 있을 뿐 압입이 아니므로 **강성을 못 잽니다.** `E_LOW_STIFFNESS`가 작동하지 않습니다
>
> 따라서 수평 연마에서 피부 접촉을 막는 유일한 수단은 **`travel_limit_mm`(기하학적 한계)**입니다. 이 값은 강성 맵에서 계산한 "경계까지의 거리 − 안전 마진"이어야 하며, 넉넉하게 잡으면 안전장치가 아니라 장식이 됩니다.

**`ProbePoint`** — 스캔과 택프리 검사가 공유
```
1. target 위 접근 높이로 이동
2. probe_speed_mms로 하강하며 Fz 감시 → 접촉점 기록
3. probe_max_depth_mm 또는 probe_max_force_n 도달까지 계속 하강
   → 하강 구간 전체의 (ΔF/Δz) 선형 회귀 기울기 = stiffness
4. measure_release=true면:
     release_speed_mms로 상승하면서 Fz 계속 측정
     → 최저값(음수)을 release_force에 기록
   false면 그냥 상승
```

> **`ProbePoint`가 이 노드에서 가장 중요합니다.** 경계 스캔과 경화 판정이 둘 다 여기에 의존합니다. `stiffness`를 단순 두 점 차분으로 구하지 말고 **하강 구간 전체의 선형 회귀**로 계산하세요. 노이즈에 훨씬 강합니다.

#### 반환값

| 액션 | 필드 | 호출자가 이걸로 판단하는 것 |
|---|---|---|
| `MoveTo` | `final_pose` | 목표 대비 오차가 허용범위인가 |
| `PickPlace` | `measured_width` | 파지 성공 여부 |
| `ContactPath` | `mean_force` / `max_force` | 힘 제어가 잘 됐는가 |
| `ContactPath` | `path_error` | 경로 이탈 정도 |
| `ContactPath` | `abort_reason` | `ABORT_LOW_STIFFNESS`면 피부 접촉 시도 |
| **`LateralContact`** | `mean_force` / `max_force` | 접근축 힘 유지 품질 (M01 성공 기준) |
| **`LateralContact`** | `max_travel_mm` | **접근축 최대 진행 거리. 한계 대비 여유 확인** |
| **`LateralContact`** | `max_jam_force_n` | 진행축 최대 저항 — 모서리 걸림 정도 |
| **`LateralContact`** | `abort_reason` | `ABORT_LATERAL_LIMIT`면 **경계 초과 진행 시도** |
| `ProbePoint` | `stiffness` | 손톱인가 피부인가 (scan_node가 판정) |
| `ProbePoint` | `release_force` | **음수면 미경화** (inspection_node가 판정) |
| `ProbePoint` | `contacted` | false면 그 위치엔 표면이 없음 |

> **판정은 이 노드가 하지 않습니다.** `ProbePoint`는 숫자만 돌려주고, "손톱이다/경화됐다"는 판단은 `scan_node`와 `inspection_node`가 합니다.

#### 피드백

| 액션 | 내용 | 주기 |
|---|---|---|
| `MoveTo` | `progress` | 10 Hz |
| `PickPlace` | `step`(0~4), `progress` | 단계 전환 시 |
| `ContactPath` | `progress`, `current_wrench` | 20 Hz |
| **`LateralContact`** | `progress`, `current_wrench`, **`travel_mm`** | 20 Hz |
| `ProbePoint` | `current_depth`, `current_force` | 50 Hz |

`LateralContact`의 `travel_mm`은 웹에 **한계 대비 게이지**로 표시하세요. 연마 중 이 값이 한계에 붙어가는 게 보이면 실기 전에 궤적을 고칠 수 있습니다.

#### 주요 에러

| 코드 | 원인 | 처리 |
|---|---|---|
| `E_NO_CONTACT` | 탐색 깊이 내 표면 없음 | 상승 후 ABORT. 지그 안착 위치 의심 |
| `E_OVERFORCE` | 힘 상한 초과 | 즉시 후퇴 후 ABORT (법선=+Z, 수평=역벡터) |
| `E_LOW_STIFFNESS` | 피부 접촉 의심 | 즉시 +Z 후퇴 + 좌표 로그 후 ABORT |
| `E_LATERAL_LIMIT` ★ | 접근축 진행 한계 초과 | **즉시 역방향 후퇴** + 좌표 로그 후 ABORT |
| `E_LATERAL_JAM` | 진행축 저항 급증 | 후퇴 후 ABORT. 접근각·경로 재검토 |
| `E_GRIP_FAILED` | 폭 피드백 불일치 | 그리퍼 Open → 후퇴 → ABORT |
| `E_TOOL_DROP` | 이동 중 폭 변화 | **즉시 정지** |
| `E_MOTION_FAILED` | dsr 서비스 실패/특이점 | 정지 후 ABORT + 원본 에러 로그 |

## 6. B계층 — 공정 노드

### 6.1 `scan_node` ★★ (Stage 0) — **2단계 스캔 (v0.2 개정)**

> **역할**: 거친 격자로 전체를 훑어 경계 후보를 찾고, 후보 부근만 촘촘히 다시 떠서 경계를 확정한다.
> **담당**: 해윤
> **이 노드가 이 프로젝트의 존재 이유입니다.**

#### 제공

| 인터페이스 | 통신 | 타입 |
|---|---|---|
| `/process/scan` | Action | `ScanBoundary` |
| `/scan/get_map` | Service | `GetStiffnessMap` |
| `/stiffness/map` | Topic(pub) | `StiffnessMap` (완료 시, TRANSIENT_LOCAL) |
| `nail_local_frame` | TF(broadcast) | 스캔으로 확정된 손톱 원점 |

#### 소비

`/skill/probe_point` (Action) · `/safety/ValidatePrecondition` (Service) · `/safety/status`

#### 파라미터

| 이름 | 타입 | 기본 | 단위 | 설명 |
|---|---|---|---|---|
| **[스캔 영역]** | | | | |
| `scan_area_x_mm` | double | `16.0` | mm | 손톱 길이축 범위 |
| `scan_area_y_mm` | double | `13.0` | mm | 손톱 폭축 범위 |
| `scan_margin_mm` | double | `2.0` | mm | 영역 바깥 여유 (경계가 밖에 있을 수 있음) |
| `frame_id` | string | `nail_frame` | — | 격자 생성 기준 프레임 |
| **[1단계 — 거친 스캔]** | | | | |
| `coarse_pitch_mm` | double | `3.0` | mm | 거친 격자 간격 |
| `coarse_min_valid_points` | int | `20` | 개 | 이보다 적으면 `E_COARSE_INSUFFICIENT` |
| `coarse_min_per_cluster` | int | `5` | 개 | 군집당 최소 점 수 |
| `cluster_method` | string | `otsu` | — | `otsu` / `kmeans2` |
| **[2단계 — 정밀 스캔]** | | | | |
| `fine_pitch_mm` | double | `1.0` | mm | 정밀 격자 간격 |
| `boundary_band_mm` | double | `3.0` | mm | 후보쌍 중점 기준 정밀 스캔 밴드 폭 |
| `fine_max_points` | int | `120` | 개 | **시간 폭주 방지 상한** |
| **[판정]** | | | | |
| `separation_margin_min` | double | `2.0` `캘` | — | 군집간거리/군집내분산. 미만이면 `E_SEPARATION_LOW` |
| `invalid_point_max_ratio` | double | `0.2` | — | 미접촉 점 비율 상한 |
| **[프로브]** | | | | |
| `probe_depth_mm` | double | `0.5` | mm | 스캔용 압입 깊이 (검사보다 얕게) |
| `probe_max_force_n` | double | `2.0` | N | 스캔용 힘 상한 |
| `probe_timeout_s` | double | `6.0` | s | 점당 타임아웃 |

#### 동작

```
1. 전제조건 확인 (핸드레스트 안착, probe 툴 장착)

─────────── 1단계: 거친 스캔 (coarse_pitch_mm = 3 mm) ───────────
2. nail_frame 기준으로 3 mm 격자 생성
     범위 = scan_area + scan_margin
     예: (16+4) × (13+4) mm → 7 × 6 = 42점
3. 각 점에 ProbePoint 호출 (measure_release=false)
     → 결과를 coarse_points에 누적, 매 점마다 feedback (stage=COARSE)
4. 유효점 검사:
     valid 개수 < coarse_min_valid_points → E_COARSE_INSUFFICIENT
5. 강성 히스토그램 군집화 (cluster_method)
     → threshold_k 산출
     → separation_margin 계산
     → 각 군집 점수 < coarse_min_per_cluster → E_SEPARATION_LOW
     → separation_margin < separation_margin_min → E_SEPARATION_LOW

─────────── 경계 후보 선정 ───────────
6. 격자 내 인접한 점 쌍 (4-이웃) 중,
     한쪽은 threshold_k 이상 · 다른 쪽은 threshold_k 미만인 쌍을 수집
     → 이 쌍의 중점이 "경계 후보점"
7. 각 경계 후보점을 중심으로 boundary_band_mm 폭의 밴드 생성
     밴드들을 합집합 → 정밀 스캔 영역

─────────── 2단계: 정밀 스캔 (fine_pitch_mm = 1 mm) ───────────
8. 정밀 스캔 영역 내부에만 1 mm 격자 생성
     이미 측정한 거친 격자 점과 겹치면 재측정하지 않음
     생성 점수 > fine_max_points → 상위 우선순위(후보점 근접 순)로 절단 + WARN
9. 각 점에 ProbePoint 호출
     → fine_points에 누적, 매 점마다 feedback (stage=FINE)

─────────── 판정 및 산출 ───────────
10. coarse_points + fine_points 를 합쳐 최종 강성 맵 구성
11. 합친 데이터로 threshold_k · separation_margin 재계산 (정밀 데이터 반영)
      → 여기서 다시 separation_margin_min 미달이면 E_SEPARATION_LOW
12. 경계 폴리곤 추출 (정밀 점 우선 사용)
      boundary_polygon  = 고강성 영역 외곽선
      forbidden_polygon = 저강성 영역
13. nail_local_frame 산출 (X=길이축, Z=표면 법선) → TF 브로드캐스트
14. /stiffness/map 발행 (coarse/fine 구분 플래그 포함)
```

**점 수와 시간 추정**

| 단계 | 점 수 | 점당 시간 | 소요 |
|---|---|---|---|
| 거친 (3 mm) | 약 42 | 1.5 s | 약 1.1 분 |
| 정밀 (1 mm) | 약 60~110 | 1.5 s | 약 1.5~2.8 분 |
| **합계** | **약 100~150** | | **약 2.6~3.9 분** |

v0.1의 0.5 mm 전면 스캔(720점, 약 18분) 대비 **약 5배 단축**입니다.

> **⚠️ 3 mm 격자의 위험: 손톱을 통째로 놓칠 수 있습니다.**
> 3 mm 간격이면 폭 13 mm 손톱에 격자선이 4~5줄만 걸칩니다. 지그 안착 위치가 조금만 어긋나도 고강성 군집의 점 수가 급감해 군집화가 무너집니다. 그래서 `coarse_min_per_cluster`(기본 5)를 두고, 미달 시 **정밀 스캔으로 넘어가지 않고 즉시 실패**시킵니다. 잘못된 후보 위에서 정밀 스캔을 돌면 시간만 쓰고 결과는 쓰레기입니다.
>
> **완화책**: 1단계에서 군집 점 수가 아슬아슬하면(`coarse_min_per_cluster` × 1.5 미만) 2 mm로 낮춰 거친 스캔을 **한 번 더** 돌리는 재시도 로직을 넣으세요. 정밀 스캔 시간을 아끼는 것보다 1단계 신뢰도가 우선입니다.

> **비유**: 안개 낀 호수에 막대를 꽂아 수심을 재는데, 먼저 3 m 간격으로 듬성듬성 꽂아 "이 근처가 물가겠구나" 하고 대충 파악한 뒤, 물가로 짐작되는 띠 위에서만 1 m 간격으로 촘촘히 꽂아 정확한 물가 선을 그리는 것입니다.

### 6.2 `sanding_node` (M01) — **수평 접근 (v0.2 개정)**

> **역할**: 손톱 표면에 **수평으로 접근**해 경계 맵 안쪽만 정접촉력으로 연마한다.
> **담당**: 주은

#### 제공 / 소비

| | 인터페이스 |
|---|---|
| 제공 | `/process/sand` (Action, `SandSurface`) |
| 소비 | **`/skill/lateral_contact`** · `/scan/get_map` · `ValidatePrecondition` · `/safety/status` |

> **v0.1에서 바뀐 점**: `ContactPath` → `LateralContact`. 다른 공정 노드와 달리 이 노드만 다른 스킬을 씁니다.

#### 파라미터

| 이름 | 타입 | 기본 | 단위 | 설명 |
|---|---|---|---|---|
| **[접근]** | | | | |
| `approach_side` | string | `free_edge` | — | `free_edge` / `left` / `right`. 접근 벡터 결정 |
| `work_plane_offset_mm` | double | `0.0` | mm | 표면 기준 작업 평면 높이 |
| `approach_pitch_deg` | double | `0.0` | deg | 접근 벡터의 표면 대비 각도 (0=완전 수평) |
| **[힘]** | | | | |
| `target_force_n` | double | `2.0` `캘` | N | 접근축 유지 접촉력 |
| `max_force_n` | double | `4.0` `캘` | N | 접근축 힘 상한 |
| `jam_force_n` | double | `4.0` `캘` | N | 진행축 걸림 판정 |
| **[경로]** | | | | |
| `passes` | int | `3` | 회 | 반복 패스 수 |
| `step_over_mm` | double | `1.5` | mm | 패스 간 이송 간격 |
| `feed_speed_mms` | double | `8.0` | mm/s | 진행축 이송 속도 |
| `max_duration_s` | double | `60.0` | s | 과연마 방지 시간 상한 |
| **[안전] ★** | | | | |
| `travel_limit_margin_mm` | double | `2.0` | mm | **경계까지 거리에서 뺄 안전 마진** |
| `forbidden_margin_mm` | double | `1.5` | mm | 금지 영역 추가 여유 |
| `require_dust_collector` | bool | `true` | — | 더스트 컬렉터 인터록 |

#### 동작

```
1. 전제조건: 안착 · sander 툴 · dust_collector_on
2. GetStiffnessMap 호출
     → found=false 또는 valid=false면 REJECT (E_NO_SCAN)

3. 접근 벡터 산출:
     approach_side에 따라 nail_local_frame 기준 수평 단위벡터 결정
       free_edge → -X (손끝에서 큐티클 방향)
       left      → +Y
       right     → -Y
     approach_pitch_deg만큼 기울임 (기본 0 = 완전 수평)

4. travel_limit_mm 계산 ★
     접근 시작점에서 approach_vector 방향으로
     forbidden_polygon(또는 boundary_polygon 반대편)까지의 최단 거리
       travel_limit_mm = 그 거리 − travel_limit_margin_mm
     계산 결과가 0 이하면 REJECT (E_INVALID_GOAL)
     ※ 이 값이 유일한 피부 접촉 방어선입니다 (§5.1 경고 참조)

5. 경로 생성:
     접근축에 수직인 평면에서 step_over_mm 간격의 왕복 경로
     boundary_polygon 내부만, forbidden_margin_mm 여유 확보

6. LateralContact 호출
     approach_vector, work_plane_z, waypoints,
     target_force_n, max_force_n, travel_limit_mm 전달

7. passes 만큼 반복 (누적 시간이 max_duration_s 넘으면 중단)
8. 결과 집계
```

> **왜 수평 접근인가**: 샌딩 비트를 손톱 법선 방향으로 누르면 국소 압력이 한 점에 집중되어 표면이 파입니다. 표면에 평행하게 대고 옆으로 밀면 접촉이 선(line)으로 분산되어 균일하게 깎입니다. 실제 시술에서 파일을 눕혀 쓰는 것과 같은 이유입니다.

> **⚠️ 수평 접근의 대가: 강성 감시를 못 씁니다.**
> `ContactPath`와 달리 압입을 하지 않으므로 `E_LOW_STIFFNESS`가 발동하지 않습니다. 피부 접촉을 막는 것은 **4번에서 계산한 `travel_limit_mm` 하나뿐**입니다.
> 따라서 `travel_limit_margin_mm`를 줄이거나 계산을 생략하면 **이 공정에는 안전장치가 아예 없어집니다.** NFR-09(침범 0건)가 이 한 줄에 걸려 있습니다.

#### 반환값

| 필드 | 호출자의 판단 |
|---|---|
| `mean_force` / `max_force` | 접근축 힘을 유지했는가 (M01 성공 기준) |
| `max_travel_mm` | **한계 대비 실제 최대 진행 거리.** 여유가 1 mm 미만이면 궤적 재설계 |
| `computed_travel_limit_mm` | 이번 세션에 적용된 한계값 (리포트 기록용) |
| `max_jam_force_n` | 모서리 걸림 정도 |
| `passes_done` / `duration_s` | 사이클 타임, 과연마 여부 |
| `abort_reason` | `ABORT_LATERAL_LIMIT`면 **경계 초과 진행 시도** — 원인 분석 필수 |

#### 피드백

`progress` + `current_wrench` + `travel_mm`, 20 Hz.
→ 웹에 힘 그래프(목표 유지선)와 **진행 거리 게이지(한계 대비)**를 함께 표시.

#### 주요 에러

| 코드 | 원인 | 처리 |
|---|---|---|
| `E_NO_SCAN` ★ | 스캔 안 됨 / valid=false | **REJECT.** 로봇 무동작 (I-10) |
| `E_LATERAL_LIMIT` ★ | 접근축 한계 초과 | 즉시 역방향 후퇴 + ABORT. **NFR-09 위반 기록** |
| `E_LATERAL_JAM` | 진행축 저항 급증 | 후퇴 + ABORT. 접근각·step_over 재검토 |
| `E_OVERFORCE` | 접근축 과압 | 후퇴 + ABORT. 과연마 방지 |
| `E_INVALID_GOAL` | `travel_limit_mm` ≤ 0 | REJECT. 접근 방향 또는 마진 재설정 |
| `E_PRECOND_FAILED` | 더스트 컬렉터 OFF 등 | REJECT (I-08) |

1. 전제조건: uv 툴 장착, 스캔 유효
2. 경로 생성
     target_region이 비어 있으면 전체 영역
     차 있으면 그 영역만 (부분 재조사, FR-23)
     → 표면 법선을 따라 standoff_mm 거리 유지
3. entry_direction에 따라 접근 경로 결정
     → 대기점에서 손톱까지 최단·최소노출 경로 (아래 경고 참조)
4. dwell_points 순회
     각 지점에서 dwell_s_per_point 만큼 정지 체류
     ※ 램프는 이미 켜져 있으므로 "정지 = 조사"
5. 총 체류 시간 집계 → actual_exposure_s
6. park_distance_mm 밖 대기 위치로 이탈
```

> **⚠️ 상시 ON의 부작용: 접근·이탈 경로에서도 조사됩니다.**
> 램프를 켠 채 들고 이동하므로, 손톱으로 접근하는 동안과 빠져나가는 동안에도 UV가 젤에 닿습니다. 결과적으로 **`actual_exposure_s`가 실제 조사량보다 작게 기록**됩니다.
>
> 대응 두 가지 중 하나를 선택하세요.
> 1. **차광 슈라우드 장착 (권장)**: 램프 헤드에 3D 프린팅으로 원뿔형 가림막을 씌워 빔을 좁힙니다. 사전 노출과 주변 산란을 동시에 줄이고, 부품 원가는 필라멘트 값뿐입니다.
> 2. **경로 설계로 회피**: `entry_direction`을 손톱 반대편에서 진입하도록 잡고, `park_distance_mm`를 충분히 확보합니다. 완전히 막지는 못합니다.
>
> 1번을 권합니다. 정량 데이터의 신뢰도와 작업자 노출이 함께 개선됩니다.

#### 반환값

| 필드 | 의미 |
|---|---|
| `actual_exposure_s` | **체류 시간 합계.** 접근·이탈 중 노출은 포함되지 않음 (위 경고 참조) |
| `dwell_completed` | 체류 지점 완료 수 |
| `mean_standoff_mm` | 평균 유지 거리 |
| `coverage_ratio` | **조사 궤적 로그.** D-04로 판정 기준에서 제외 — 기록용 |

#### 피드백

`progress` + `current_dwell_index` + `elapsed_dwell_s`, 10 Hz.

> **v0.1의 `uv_on` 필드는 의미가 없어졌습니다** (항상 true). 대신 `elapsed_dwell_s`를 표시해 "지금 몇 초째 굽고 있는가"를 보여주세요.

#### 주요 에러

| 코드 | 원인 | 처리 |
|---|---|---|
| `E_SAFETY_BLOCKED` | 실행 중 안전 결함 | **즉시 대기 위치로 이탈** 후 ABORT |
| `E_MOTION_FAILED` | 경로 실패 | 이탈 후 ABORT |
| `E_NO_SCAN` | 스캔 무효 | REJECT |
| `E_PRECOND_FAILED` | uv 툴 미장착 | REJECT |
| `E_TIMEOUT` | `max_duration_s` 초과 | 이탈 후 ABORT |

> **`E_SAFETY_BLOCKED` 처리가 v0.1보다 중요해졌습니다.** permit이 없으므로 "소등"이라는 선택지가 없습니다. 안전 결함 시 할 수 있는 건 **물리적으로 치우는 것**뿐이므로, 이탈 동작이 확실히 실행되는지 확인하세요.

### 6.6 `inspection_node` ★ (M06) — **3점 고정 (v0.2 개정)**

> **역할**: 프로브로 경화면을 눌렀다 떼면서 택프리 여부를 판정한다.
> **담당**: 희재
> **D-04 확정으로 이 노드가 품질 판정의 유일한 근거입니다.**

#### 제공 / 소비

| | 인터페이스 |
|---|---|
| 제공 | `/process/inspect` (Action, `InspectCure`) · `/validation/result` (Topic pub) |
| 소비 | `/skill/probe_point` · `/scan/get_map` · `ValidatePrecondition` |

#### 파라미터

| 이름 | 타입 | 기본 | 단위 | 설명 |
|---|---|---|---|---|
| **[검사점 — v0.2 고정]** | | | | |
| `sample_point_count` | int | `3` | 개 | **중앙 · 좌측 · 우측 고정** |
| `center_offset_x_ratio` | double | `0.0` | — | 중앙점의 길이축 위치 (0=손톱 중심) |
| `side_offset_y_ratio` | double | `0.6` | — | 좌우점의 폭축 위치 (경계까지 거리 대비 비율) |
| `min_edge_clearance_mm` | double | `1.5` | mm | 좌우점이 경계에서 최소 이 거리는 떨어질 것 |
| **[판정]** | | | | |
| `tack_threshold_n` | double | `0.15` `캘` | N | 이탈 인장력 절대값 임계. 초과 시 미경화 |
| `require_all_pass` | bool | `true` | — | 3점 모두 PASS여야 통과 |
| **[프로브]** | | | | |
| `probe_depth_mm` | double | `0.3` | mm | 검사용 압입 깊이 (스캔보다 얕게) |
| `probe_max_force_n` | double | `1.5` `캘` | N | **젤을 뚫지 않을 상한** |
| `release_speed_mms` | double | `1.0` | mm/s | 이탈 속도 — 느릴수록 점착 신호가 뚜렷 |
| `point_timeout_s` | double | `10.0` | s | 점당 타임아웃 |

#### 동작

```
1. 전제조건: probe 툴 장착, 스캔 유효
2. GetStiffnessMap → boundary_polygon으로부터 3점 좌표 산출

     center : nail_local_frame 원점 + center_offset_x_ratio
     left   : 중앙에서 +Y 방향, 경계까지 거리 × side_offset_y_ratio
     right  : 중앙에서 -Y 방향, 경계까지 거리 × side_offset_y_ratio

     좌우점이 min_edge_clearance_mm 를 못 지키면
       → 비율을 자동으로 줄여 마진 확보
       → 그래도 불가하면 해당 점을 건너뛰고 WARN (2점 검사로 진행)

3. 3점 각각에 대해:
     ProbePoint(measure_release=true) 호출
     판정:
       |release_force| > tack_threshold_n  →  미경화 (FAIL)
       그 외                                →  경화   (PASS)
     ValidationResult 생성 → /validation/result 발행

4. require_all_pass=true이면 하나라도 FAIL 시 passed=false
5. FAIL 좌표를 fail_points에 수집 → REWORK 대상
```

**왜 중앙 + 양 사이드인가**

| 점 | 노리는 것 |
|---|---|
| 중앙 | 기준값. 조사가 가장 잘 되는 지점이므로 여기가 FAIL이면 조사 자체가 실패 |
| 좌 · 우 | **사이드월 음영 사각지대.** 이 프로젝트가 해결하겠다고 주장한 바로 그 부위 |

> **좌우 두 점이 이 프로젝트의 주장을 검증합니다.** 중앙만 검사하면 일괄 조사 방식과 결과가 같아서, 국소 조사의 우위를 보일 수 없습니다. 좌우점을 경계에 최대한 붙이되(`side_offset_y_ratio` 상향), `min_edge_clearance_mm`는 지키세요.

> **⚠️ 3점의 한계를 문서에 명시하세요.**
> 3점으로는 **국소적인 작은 미경화 반점을 검출할 수 없습니다.** 검사한 3곳이 우연히 다 경화된 경우 PASS가 나옵니다. 결과 보고 시 "손톱 전체가 경화됨"이 아니라 **"검사한 3개 지점이 경화 기준을 만족함"**으로 기술하세요. BRD의 R7(과대 주장 리스크)이 여기에 직접 걸립니다.

> **비유**: 페인트가 말랐는지 손가락으로 살짝 눌러보는 것과 같습니다. 덜 말랐으면 뗄 때 끈적하게 딸려옵니다. 그 "딸려오는 힘"이 음(-)의 Fz입니다.

#### 반환값

| 필드 | 호출자의 판단 |
|---|---|
| `passed` | orchestrator가 다음 레이어로 갈지 REWORK로 갈지 결정 |
| `fail_points` | **REWORK 시 이 좌표만 재조사** (FR-23) |
| `results[]` | 3점 각각의 `release_force`·`stiffness`·판정 → DB (BR-15) |
| `points_measured` | 실제 측정 점 수 (마진 부족으로 2점일 수 있음) |

#### 피드백

`progress` + `last_result`, **점마다** 발행 (3점이므로 3회).

#### 주요 에러

| 코드 | 원인 | 처리 |
|---|---|---|
| `E_NO_CONTACT` | 표면 미검출 | 해당 점을 판정 불가로 표시, 나머지 계속 |
| `E_OVERFORCE` | 프로브 과압 | ABORT. **미경화 젤을 뚫었을 가능성** — 도포면 손상 |
| `E_NO_SCAN` | 경계 정보 없음 → 3점 좌표 산출 불가 | REJECT |
| `E_PRECOND_FAILED` | probe 툴 미장착 | REJECT |

> **⚠️ 산소 저해층**
> 일반 탑젤은 정상 경화돼도 표면에 끈적임이 남아 **완전 경화품도 FAIL**이 됩니다. 논와이프 탑젤을 못 구하면, 판정 시점을 **레이어 사이(베이스 경화 직후)**로 옮기고 `tack_threshold_n`을 재보정해야 합니다. 이 결정은 코드가 아니라 **소재 확보 결과**에 달려 있으므로 Day 1에 확인하세요.

**주요 에러**: `E_GRIP_FAILED` · `E_STONE_MISS` · `E_OVERFORCE`

> **`verify_enabled` 기본값을 `false`로 둔 이유**: 프로브로 지름 2~3 mm 스톤의 중심을 찾는 건 격자 스캔을 다시 도는 것과 같습니다. 시간이 없으면 **검증 없이 "부착만" 구현**하고 `position_error = -1`을 반환하세요. 검증을 흉내 내는 것보다 안 했다고 명시하는 편이 낫습니다.

## 7. `safety_monitor` ★★

> **역할**: 안전 상태를 감시하고 전제조건을 검증한다.
> **담당**: 희재

### 7.0 ⚠️ v0.2 UV 정책 변경 — 반드시 읽을 것

**v0.1에서는 `safety_monitor`가 UV Digital Output을 단독 소유하고 permit 없이는 점등이 불가능했습니다. v0.2에서는 이 구조가 폐지되고 램프가 상시 ON으로 동작합니다.**

이는 실습 편의를 위한 결정이며, 결과적으로 **소프트웨어 안전 계층이 UV에서 완전히 사라집니다.** 즉:

- E-Stop을 눌러도 **소프트웨어는 램프를 끄지 못합니다**
- 툴을 파지한 채 이동하는 동안에도 램프는 켜져 있습니다
- 노드가 죽거나 통신이 끊겨도 램프는 계속 조사합니다

따라서 **아래 물리적 통제가 이제 유일한 방어선**입니다. 하나라도 빠지면 방어선이 없습니다.

| # | 통제 | 상태 |
|---|---|---|
| 1 | 작업 영역을 UV 차단 아크릴(황색)로 차폐 | **필수** |
| 2 | 작업자·촬영자 전원 UV 차단 고글 착용 | **필수** |
| 3 | 램프 헤드 차광 슈라우드 (§6.5 권장안) | **강력 권장** |
| 4 | 램프 전원선을 **E-Stop 회로에 직렬 결선** (하드웨어) | **강력 권장** |
| 5 | 수동 마스터 스위치를 작업자 손 닿는 곳에 배치 | **필수** |
| 6 | 미사용 시 UV 툴을 랙에 **광축이 랙 안쪽을 향하도록** 반납 (`uv_park_facing`) | **필수** |

> **4번은 permit 폐지와 모순되지 않습니다.** permit은 소프트웨어 승인 절차이고, 4번은 전원 라인 물리 결선입니다. 배선 하나로 "E-Stop 누르면 램프도 꺼진다"가 복원되므로, 가능하면 반드시 하세요. **소프트웨어를 못 믿는 상황일수록 하드웨어 인터록의 값이 올라갑니다.**
>
> 365/405 nm는 통증이 지연되어 나타나므로 노출을 인지하기 어렵습니다. 실습 중 "잠깐인데 괜찮겠지"가 가장 위험합니다.

| 인터페이스 | 통신 | 타입 |

| `/safety/status` | Topic(pub) | `SafetyState`, 20 Hz, TRANSIENT_LOCAL |

**삭제됨**: `/safety/uv_permit` (`RequestUvPermit`)

### 소비

### 동작

**① 상태 수집 루프 (`publish_rate_hz`)**
```
E-Stop DI · 안착 센서 DI · 더스트 컬렉터 DI 읽기

**② E-Stop 처리 (최우선)**
```

   ① safe_to_move = false 발행
   ② ABORT 래치 설정 (ResetSafety 전까지 유지)
   ③ FAULT_ESTOP을 active_faults에 등록
```

> **v0.1에는 "UV DO OFF를 모션 정지보다 먼저"라는 항목이 ①에 있었습니다. v0.2에서는 소프트웨어가 UV를 끌 수 없으므로 이 단계가 사라졌습니다.** §7.0의 4번(하드웨어 결선)이 이 역할을 대신합니다.

**③ 전제조건 검사 (`ValidatePrecondition`)**

| stage | 검사 항목 |
|---|---|
| SCAN | 안착 · probe 툴 |
| SAND | 안착 · sander 툴 · **더스트 컬렉터 ON** · 스캔 valid |
| BRUSH | 안착 · brush 툴 |
| COAT | 안착 · coater 툴 · 스캔 valid |
| CURE | 안착 · uv 툴 · 스캔 valid |
| INSPECT | 안착 · probe 툴 · 스캔 valid |
| STONE | 안착 · tweezers 툴 |

### 반환값

| 인터페이스 | 필드 | 의미 |
|---|---|---|
| `ValidatePrecondition` | `ok` | false면 호출자는 goal REJECT |
| | `blocking_reasons[]` | **막힌 이유 전부.** 하나만 주지 말 것 |
| `ResetSafety` | `remaining_faults[]` | **비어야 리셋 성공** |

### 결함 코드

| 코드 | 발생 | 해제 조건 |
|---|---|---|
| `FAULT_ESTOP` | E-Stop 눌림 | 해제 + `ResetSafety` |

> **`ResetSafety`는 무조건 성공시키지 마세요.** 물리적 원인이 남아 있는데 리셋이 되면 인터록이 무의미해집니다. `remaining_faults`가 비었을 때만 `ok=true`입니다. `auto_reset` 파라미터는 존재하지만 **`true`로 두면 이 노드의 존재 의미가 사라집니다.**

> **역할**: 세션 상태 머신을 돌리고, 재작업 루프를 관리한다. **직접 로봇을 움직이지 않는다.**

| `stage_timeout_inspect_s` | double | `60.0` | s | 3점이므로 짧게 |
| `tool_change_timeout_s` | double | `60.0` | s | |
| `abort_return_home` | bool | `true` | — | ABORT 시 HOME 복귀 |

### 동작

**손가락 1개(D-07)이므로 반복은 레이어 하나뿐입니다.**

```
PRECHECK  → 안착 · 툴 랙 전수 · 통신 · E-Stop 해제 확인
   ↓
SCAN      → ChangeTool(probe) → 2단계 스캔
             map.valid == false 이면 ABORT
   ↓
SAND      → ChangeTool(sander) → 수평 연마 (LateralContact)
   ↓
BRUSH     → ChangeTool(brush) → 더스트 제거      [enable_brush]
   ↓
┌─── 레이어 루프 (layer_index = 0 .. layer_total-1) ────┐
│ COAT    → ChangeTool(coater) → 도포                    │
│ CURE    → ChangeTool(uv) → 경화                        │
│ INSPECT → ChangeTool(probe) → 3점 택프리 검증           │
│    PASS → 다음 레이어                                   │
│    FAIL → REWORK: fail_points만 CURE 재실행             │
│             (exposure × rework_exposure_scale)          │
│             rework_count++                              │
│             > max_rework 이면 ABORT(E_REWORK_EXCEEDED)  │
└─────────────────────────────────────────────────────────┘
   ↓
STONE     → ChangeTool(tweezers) → 스톤 부착      [enable_stone]
   ↓
FINISH → 결과 집계 → REPORT
```

> **툴 교체 횟수를 세어 보세요.** 레이어당 `coater → uv → probe` 3회 교체입니다. `layer_total=2`면 스캔·연마·브러시 포함 **총 9회.** 교체 1회 15초면 **약 2분 15초가 툴 교체에만** 쓰입니다.
>
> **v0.2에서 UV 상시 ON이 되면서 D-05(UV 손목 상시 장착, C안)의 성격이 바뀌었습니다.** 상시 장착하면 교체가 레이어당 2회로 줄지만, **켜진 램프를 계속 손목에 달고 전 공정을 도는 것**이 됩니다. 연마·도포 중에도 UV가 작업 영역을 비추게 되어, 도포한 젤이 의도치 않게 굳습니다. **v0.2 조건에서는 C안을 권장하지 않습니다.** 랙 반납 방식을 유지하세요.

### 반환값

| 필드 | 의미 |
|---|---|
| `scan_result` | 세션의 강성 맵 (리포트에 첨부) |
| `all_results[]` | 레이어별 3점 판정 이력 전부 → DB (BR-15) |
| `total_rework` | 재작업 총 횟수 → NFR-11 산출 근거 |
| `abort_reason` | 중단 사유 |

### 피드백

`ProcessState` 전체를 그대로 실어 보냅니다. 상태 전이 시 즉시 + 1 Hz.
`/process/status` 토픽에도 **같은 내용을 동시 발행**합니다.

> **왜 둘 다 발행하나**: 액션 feedback은 goal을 보낸 클라이언트만 받습니다. 웹 화면 여러 개가 동시에 볼 수 있으므로 토픽도 필요합니다.

### 주요 에러

| 코드 | 원인 | 처리 |
|---|---|---|
| `E_NO_SCAN` | 스캔 결과 invalid | 즉시 ABORT. 이후 공정 시도조차 안 함 |
| `E_REWORK_EXCEEDED` | 재작업 한도 초과 (BR-09) | ABORT |
| `E_SAFETY_BLOCKED` | 실행 중 안전 결함 | **하위 액션 전부 cancel** 후 ABORT |
| `E_CANCELLED` | 사용자 취소 (BR-16) | 하위 cancel → 툴 반납 → HOME |

**ABORT 공통 처리**
```
① 진행 중인 하위 액션 전부 cancel (완료 대기)
② 툴을 들고 있으면 ChangeTool("none")으로 반납 시도
     ※ UV 툴이면 반납 우선순위 최상 — 켜진 램프를 들고 멈추면 안 됨
③ HOME 복귀
④ ProcessState(stage=STAGE_ABORTED) 발행
⑤ 자동 재시작 안 함 (NFR-06)
```

> **②에서 반납이 실패해도 ③은 진행해야 합니다.** 단, **UV 툴 반납 실패는 예외적으로 심각합니다** — 켜진 램프를 든 채 HOME으로 가면 이동 경로 전체가 조사됩니다. UV 반납 실패 시에는 HOME 복귀 대신 **현재 위치에서 정지하고 수동 개입을 요청**하세요(램프를 사람이 끄거나 회수). 반납 실패는 `active_faults`에 남깁니다.

| Fz (접촉 전) | 노이즈만 (`noise_sigma_n`) |
| Fz (접촉 후) | `F = k × (z_cmd − z_surface)` + 노이즈 |
| 강성 `k` | 타원 내부면 `k_nail`, 외부면 `k_skin`, 경계는 `k_transition_mm` 폭으로 부드럽게 전이 |
| **수평 접촉력** | 접근 벡터 방향 진행량에 비례. 타원 경계 넘으면 저항 급증(`lateral_jam` 재현) |
| 택프리 릴리즈 | `cured=false` 또는 `uncured_region`에 해당하면 이탈 시 음의 Fz 주입 |

> **`uncured_region`으로 REWORK 루프를 로봇 없이 시험하세요.** `left`로 두면 좌측 검사점만 FAIL이 나고, orchestrator가 그 좌표만 재조사하는지 확인할 수 있습니다. 이게 폐루프 검증의 mock 버전입니다.

> **`k_transition_mm`을 0으로 두지 마세요.** 실제 손톱-피부 경계는 계단이 아니라 완만한 전이입니다. 0으로 두고 개발하면 `separation_margin` 계산이 실제보다 낙관적으로 나와, 실기에서 처음 `E_SEPARATION_LOW`를 만나게 됩니다.

`inject_fault`가 있어야 **인터록 테스트 I-01~I-10을 로봇 없이 대부분 돌릴 수 있습니다.**

## 13. 구현 체크리스트

각자 자기 노드를 끝냈다고 선언하기 전에 아래를 확인하세요.

- [ ] `/safety/status`를 구독하고, `safe_to_move=false`에 반응한다
- [ ] goal 수락 전에 `ValidatePrecondition`을 호출한다
- [ ] 서비스 호출이 콜백 데드락을 일으키지 않는다 (콜백 그룹 분리 확인)
- [ ] 취소 요청 시 하위 액션까지 전파한다
- [ ] ABORT / CANCEL 뒷정리가 **같은 함수**로 처리된다
- [ ] **이탈 방향이 접근 방향에 맞다** (법선 = +Z, 수평 = 접근 역벡터)
- [ ] `result.error`에 4장의 표준 코드만 넣는다 (자유 서술 없음)
- [ ] 모든 ABORT 로그에 에러 코드와 좌표/측정값이 있다
- [ ] **하드코딩 상수 없이 전부 `declare_parameter`로 선언했다** (§12에 등록됨)
- [ ] `use_mock_hardware` 파라미터를 지원한다
- [ ] mock 환경에서 단독 실행이 된다 (다른 노드 없이)

**담당자별 추가 확인**

- [ ] **sanding**: `travel_limit_mm`를 강성 맵에서 계산한다 (상수 하드코딩 금지) ★
- [ ] **scan**: 1단계 군집 점 수 미달 시 2단계로 넘어가지 않는다
- [ ] **inspection**: 좌우 검사점이 `min_edge_clearance_mm`를 지킨다
- [ ] **curing**: 안전 결함 시 이탈 동작이 실제로 실행된다 (permit이 없으므로 유일한 대응)
- [ ] **orchestrator**: UV 툴 반납 실패 시 HOME 복귀하지 않고 정지한다
- [ ] **safety**: `ResetSafety`가 `remaining_faults` 비었을 때만 성공한다
