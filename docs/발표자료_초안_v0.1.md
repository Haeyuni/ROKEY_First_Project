# 발표자료 초안 (PPT 슬라이드 내용)

> 실제 코드(`src/`, `web/`) 기준으로 작성. 이미지 삽입 위치는 `!image.png`로 표시.

## 1. 시스템 구성

```
Frontend (React 키오스크)
↓
Backend (FastAPI)
↓
ROS2 Gateway (nail_bridge / rosbridge_server, 화이트리스트 방식)
↓
Robot (Doosan 협동로봇 — orchestrator → process → skill 계층)
```

## 2. 인터페이스 구현

!image.png *(nail_bridge 화이트리스트 구조도 삽입 위치)*

### Topic
```
/process/status   (ProcessState)
/safety/status    (SafetyState)
/tool/status      (ToolState)
/robot/pose       (PoseStamped, 50Hz)
```
> 웹에는 이 중 `/process/status`, `/safety/status`만 nail_bridge 화이트리스트로 노출됨

### Service
```
/safety/validate  (공정 시작 전 사전검증)
/safety/reset     (E-Stop/통신두절 복구, confirm=true 필요)
/tool/get_info
```

### Action (5공정 + 로봇 제어의 핵심 — Service보다 Action 비중이 큼)
```
/session/run        (RunSession — 주문 시작=goal 전송, 취소=cancel_goal)
/process/sand, /process/brush, /process/coat, /process/cure, /process/place_stone
/skill/move_to, /skill/pick_place, /skill/contact_path, /skill/lateral_contact
/tool/change
```

## 3. ROS2 Node 구성

### 노드 구성
```
session_orchestrator_node   (C: 세션 상태머신, 5공정 순차 호출)
sanding/brushing/coating/curing/stone_node   (B: 공정별 ActionServer)
robot_skill_node / tool_manager_node        (A: 로봇 동작 원자 스킬)
safety_monitor_node                          (전 구간 안전 감시, /safety/status 발행)
web_bridge_node (nail_bridge)                (rosbridge 기반 ROS2 ↔ 웹 게이트웨이)
```

### Node Graph
```
Web(FastAPI) → nail_bridge(Gateway) → session_orchestrator_node
   → [sand → brush → coat → cure → stone] (5개 process 노드)
   → robot_skill_node / tool_manager_node → Doosan Robot

safety_monitor_node : 전 노드를 병렬로 감시, /safety/status 브로드캐스트
```

## 13. 예외, 오류 처리 (2개 이상 구현)

- 안전 복구
```
safety_monitor_node의 latched fault(E-Stop/통신두절)
/safety/reset(confirm=true)로만 해제, 조건 미해소 시 리셋 거부
```

- 비상 정지
```
Doosan robot_state E-Stop 코드 감지 → FAULT_ESTOP 래치
→ /safety/status 즉시 브로드캐스트 → 전 노드 동작 차단
```

- 주문 취소
```
프론트 취소 버튼 → POST /api/sessions/{id}/cancel
→ rosbridge cancel_goal(RunSession) → orchestrator 중단
→ result_code = CANCELLED 저장
```

- 동작 이상 발생
```
ErrorCode 심각도 분기: WARN(기록) / RETRY(자동 재시도) / ABORT·SAFETY(공정 중단)
AlertModal 팝업으로 사용자 알림
```

## 14. 문제점

```
rosbridge WebSocket 경유 통신 지연 (특히 /robot/pose 50Hz 스트림)
티칭 좌표 기반 오차 누적 — 힘/토크 센서 부재로 접촉 검증 불가
동시 세션 요청 시 단일 로봇 자원 경합
```

## 15. 개선 방안

```
세션 요청 Queue 적용 (단일 로봇 자원 순차 배정)

심각도별 자동 재시도 상한 및 재연결 로직 개선
```
