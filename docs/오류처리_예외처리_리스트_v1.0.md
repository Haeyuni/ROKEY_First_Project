### 1. 안전 결함 (safety_monitor_node)

로봇을 실제로 멈추는 유일한 신호는 `/safety/status.safe_to_move` 하나뿐이다.

| 결함 | 트리거 조건 | 처리 | 해제 |
| --- | --- | --- | --- |
| `FAULT_ESTOP` | 두산 컨트롤러 `robot_state`가 EMERGENCY_STOP로 전이 | 래치, `safe_to_move=false` | E-Stop 해제 + `ResetSafety(confirm=true)` |
| `FAULT_COMM_LOST` | 컨트롤러 상태 폴링 실패/타임아웃(`heartbeat_timeout_ms=3000`) | 래치, `safe_to_move=false` | 통신 복구 + `ResetSafety(confirm=true)` |
- 결함은 물리 원인이 사라져도 자동으로 안 풀린다(`auto_reset=false` 기본).
`confirm=false`로 호출하면 잔여 결함만 보고하고 아무것도 바꾸지 않는다.
- `auto_reset=true`는 로그에 경고를 남긴다.

### 2. 표준 에러 코드 (전 노드 공통, `ErrorCode.msg`)

| 코드 | 심각도 | 대표 발생 위치 | 원인 | 처리 |
| --- | --- | --- | --- | --- |
| `E_INVALID_GOAL` | ABORT | orchestrator/모든 process·skill 노드 | 필수값 누락, 허용 목록 밖 값, 기하 한계 위반 | goal REJECT 또는 실행 중 ABORT |
| `E_SAFETY_BLOCKED` | SAFETY | 전 노드 goal_callback, 실행 루프 | `safe_to_move=false` 또는 안전 상태 수신 만료(`safety_status_timeout_s=1.0`) | 새 goal 거부, 실행 중 즉시 중단 |
| `E_PRECOND_FAILED` | ABORT | orchestrator PRECHECK, `/safety/validate` | 통신 두절·E-Stop·툴 랙 설정 누락 등 사전조건 미충족 | 이동 전 거부 |
| `E_TIMEOUT` | ABORT | `_call_action` 공통 뼈대(모든 하위 액션) | 액션/드라이버 응답이 스테이지별 타임아웃 초과 (sand 120s·brush 60s·coat 90s·cure 150s·stone 90s·tool_change 180s) | 하위 goal 취소 후 세션 이탈 |
| `E_CANCELLED` | NONE | `_call_action` | 사용자/상위 취소 요청 | 하위 취소 전파 후 이탈, 결과는 `RESULT_CANCELLED` |
| `E_COMM_LOST` | ABORT | orchestrator↔하위 액션 서버 연결 | 액션 서버 미기동, goal 전송/응답 실패 | 세션 중단 |
| `E_MOTION_FAILED` | ABORT | robot_skill_node(이동/접촉 감시) | TF 조회 실패, DSR 명령 실패, 최종 자세 오차 초과, 또는 컨트롤러가 이동을 조용히 거부(BUSY 전이 없이 끝남)해 `_verify_position_reached`가 실제 도달 여부를 재검사해 걸러냄(허용오차 `move_pose_tolerance_mm=1.0mm`) | 정지 후 이탈 |
| `E_LATERAL_LIMIT` | SAFETY | sanding_node (`_compute_travel_limit`) | 티칭 경계 기준 `engagement_depth_mm`이 `travel_limit_mm`(경계까지 거리 − margin) 초과 | 로봇을 움직이기 전 REJECT — 피부 접촉 방지의 실질적 방어선. **단, goal에 수동 waypoints를 직접 넘기면 이 계산 자체를 건너뛴다 — 그 경우 안전은 전적으로 호출자(티칭값) 책임** |
| `E_GRIP_FAILED` | RETRY(선언)/ABORT(stone_node) | tool_manager_node, robot_skill_node(PickPlace), stone_node | 그리퍼 서비스 명령 실패 | 현재 툴을 `NONE`으로 간주, 세션 ABORT — **재시도 로직 없음**(7장 참고) |

### 3. 경로 안전 (연마·코팅·브러싱 공통 패턴)

| 항목 | 내용 |
| --- | --- |
| 경계 검출 방식 | **티칭 좌표 + `travel_limit_mm` 안전 마진**으로 방어한다 |
| 티칭 값 검증 | `taught_surface.py`: YAML 티칭 값 파싱 단계에서 `SurfaceConfigError`로 실패 — 좌표 6값 중 하나라도 없거나(`None`), `configured: true`가 아니면 실기 이동 자체를 막는다. |
| 작업 영역 이탈 처리 | `ContactPath`류(브러시/코터 6-Pose 경로)는 `allowed_polygon`(티칭 꼭짓점) 밖 waypoint를 만나면 이동 없이 즉시 중단, 종료 시 작업면에서 이탈한다. |
| 실행 중 감시 | `/safety/status`, 취소 요청, 스테이지 타임아웃, DSR 결과, 최종 자세 오차를 계속 감시한다(`robot_skill_node._monitor`). |

### 4. 툴 교체 · 그리퍼 (tool_manager_node)

| 항목 | 내용 |
| --- | --- |
| PickPlace 성공 판정 | 이동+그리퍼 명령 성공— 파지/반납/스톤 부착은 육안 확인이 필수. 그리퍼(OnRobot RG2) 서비스 자체도 Modbus 전송 성공만으로 `success=True`를 반환하는 하드웨어 한계가 있어, `_wait_gripper_idle()`이 `/joint_states`의 손가락 부하를 폴링해 실제 정지를 별도로 확인한다(폴링 불가 시에는 판단 불가로 그냥 성공 처리). |
| 툴 반납 실패 | 현재 보유 상태를 숨기지 않고 그대로 발행 후 중단한다. |
| UV 반납 실패 (특수 처리) | HOME 복귀를 생략하고 현재 위치에서 정지한다(켜진 UV 램프를 든 채 이동하면 경로 전체가 조사되는 위험 때문). 로그로 수동 개입을 요청할 뿐, `active_faults`에는 기록하지 못한다(오케스트레이터에 해당 서비스 권한 없음). |
| PRECHECK 툴 랙 확인 | `rack_config.yaml` 설정 완결성만 검증한다. |

### 5. 세션 취소 · 타임아웃 · ABORT 공통 처리 (session_orchestrator_node)

`_call_action` 공통 뼈대가 실패/취소를 감지했을 때 타는 정리 경로:

| 순서 | 동작 |
| --- | --- |
| 1 | RunSession 실패/취소 감지 |
| 2 | 현재 하위 액션(process/skill) goal 취소, 결과 대기(`child_cancel_wait_s=10s`) |
| 3 | 결과 미수신 시 `E_COMM_LOST`로 강등 |
| 4 | 보유 툴 있으면 반납 시도 (실패해도 무시하고 다음 단계로, UV는 예외) |
| 5 | `abort_return_home=true`면 HOME(`rack_transit`) 복귀 시도 |
| 6 | `ProcessState.stage=ABORTED` 발행, `RunSession` result 반환 |

| 결과 코드 | 사용 조건 |
| --- | --- |
| `RESULT_COMPLETED` | 정상 완료 |
| `RESULT_CANCELLED` | 취소 |
| `RESULT_ABORTED_SAFETY` | `E_SAFETY_BLOCKED`일 때만 |
| `RESULT_FAILED` | 그 외 모든 실패 |
- 타임아웃도 취소와 동일한 정리 경로를 탄다.

### 6. 웹 백엔드 ↔ ROS2 연동 계층 (web/backend)

| 상황 | 트리거 | 처리 |
| --- | --- | --- |
| 세션 생성 시 소재 불허 | `target_material`이 허용 목록 밖 | HTTP 400 |
| 세션 생성 시 중복 | 진행 중(`result_code IS NULL`) 세션 존재 | HTTP 409 |
| RunSession 액션 서버 무응답 | goal 전송 후 3초(`run_session_timeout_s`) 내 첫 feedback/result 없음 | `RunSessionTimeoutError` → 세션을 DB에 `FAILED`로 즉시 기록, HTTP 503 |
| 세션 취소 요청 | 세션 없음/이미 종료/취소할 활성 goal 없음 | 각각 404 / 409 / 409 |
| rosbridge_server(9090) 연결 끊김 | roslibpy `on("close")` | 로그만 남김 — REST는 살아있으나 실시간 중계·세션 시작 불가 |
| WS 클라이언트 연결 끊김 | `WebSocketDisconnect` 또는 전송 예외 | 서버가 클라이언트 목록에서 조용히 제거 |
| 프론트 WS 연결 끊김 | `ws.onclose`/`onerror` | 2초 간격 자동 재연결(`RECONNECT_DELAY_MS`), 재접속 시 서버가 safety/state 스냅샷 재전송 |
| WS `"result"` 이벤트 유실 | 결과가 나가는 순간 클라이언트가 끊겨 있었음 | 프론트가 `ProcessState.stage`가 `FINISH`/`ABORTED`로 넘어온 것을 감지해 `GET /api/sessions/{id}/report`로 결과를 재조회, 세션 ID로 중복 처리 방지 |
| 이벤트/상태 DB 저장 실패 | Postgres 오류 등 | 예외를 흡수하고 로그만 남김 — 실시간 중계·공정 진행에는 영향 없음(FR-45) |
