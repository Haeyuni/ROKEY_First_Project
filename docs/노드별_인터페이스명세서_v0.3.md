# 노드별 인터페이스 명세서

**문서 ID** NIS-NAIL-v0.3 · **상위 문서** SDS-NAIL-v0.3 · **개정일** 2026-08-26

이 문서는 현재 소스와 `src/nail_msgs` 계약을 설명한다. 필드의 최종 기준은
`docs/인터페이스정의서_IDS.md`와 실제 `.msg`, `.srv`, `.action` 파일이다.

## 1. 시스템 전제

- 실제 장비는 두산 M0609과 OnRobot RG2이다.
- 외부 카메라·손 안착·더스트 센서는 없다. 두산 컨트롤러의 계산 외력은 독립
  Probe 검증에서만 읽으며, 생산 공정의 힘 제어나 합격 판정에는 사용하지 않는다.
- `nail_perception`은 설정 경계용 2차원 기하 함수와 독립
  `/process/scan_boundary`를 제공한다. 카메라 입력이나 영상 판정 기능은 없다.
- 손톱 위치는 `nail_local_frame`, 크기는 `nail_region` 설정값이다. 실행 중
  측정하거나 자동 보정하지 않는다.
- `ContactPath`와 `LateralContact`는 티칭 좌표를 순서대로 따라가는 위치 기반
  스킬이다. 공통 안전 수단은 기하 경계, `/safety/status`, 취소, 타임아웃,
  드라이버 결과 확인과 종료 후 이탈이다.
- 그리퍼는 명령만 보낸다. 폭 되읽기나 파지 성공 판정은 없으므로 실제 파지는
  운영자가 눈으로 확인한다.
- UV 램프는 상시 ON이며 소프트웨어로 끌 수 없다.

## 2. 노드 관계

```text
web -> /session/run -> session_orchestrator
                         |-> tool_manager -> PickPlace -> robot_skill_node
                         |-> sanding_node  -> LateralContact
                         |-> brushing_node -> ContactPath
                         |-> coating_node  -> ContactPath
                         |-> curing_node   -> MoveTo
                         `-> stone_node    -> PickPlace, MoveTo

safety_monitor -> /safety/status -> 모든 동작 노드

독립 검증: scan_boundary_node -> ProbePoint -> robot_skill_node
```

| 노드 | 제공 | 주요 소비 |
|---|---|---|
| `robot_skill_node` | `/skill/move_to`, `/skill/pick_place`, `/skill/contact_path`, `/skill/lateral_contact`, `/skill/probe_point`, `/robot/pose` | DSR 이동·그리퍼·외력 조회, TF, `/safety/status` |
| `tool_manager` | `/tool/change`, `/tool/get_info`, `/tool/status` | `PickPlace`, DSR TCP, `/safety/status` |
| `sanding_node` | `/process/sand` | `LateralContact`, `ValidatePrecondition`, 티칭 경계 |
| `brushing_node` | `/process/brush` | `ContactPath`, `ValidatePrecondition`, 티칭 경계 |
| `coating_node` | `/process/coat` | `ContactPath`, `ValidatePrecondition`, 티칭 경계 |
| `curing_node` | `/process/cure` | `MoveTo`, `ValidatePrecondition` |
| `stone_node` | `/process/place_stone` | `PickPlace`, `MoveTo`, `ValidatePrecondition` |
| `scan_boundary_node` | `/process/scan_boundary` | `ProbePoint`, `ValidatePrecondition` |
| `safety_monitor` | `/safety/status`, `/safety/validate`, `/safety/reset` | DSR 컨트롤러 상태, `/tool/status` |
| `session_orchestrator` | `/session/run`, `/process/status` | 툴·공정 액션과 `/safety/status` |

## 3. 공통 규약

### 3.1 액션 수명주기

1. 필수 필드와 범위를 검사한다.
2. 안전 판정은 `safety_monitor`가 단일하게 담당한다.
3. 공정 노드는 `/safety/validate`를 비동기로 호출해 현재 툴과 안전 상태를 확인한다.
4. 실행 중에는 취소와 단계별 타임아웃을 계속 확인한다.
5. 하위 액션을 호출한 노드는 상위 취소를 하위 goal에 전파한다.
6. 경로 액션은 성공, 실패, 취소 후 작업 영역에서 이탈한다.

`REJECT`는 로봇이 움직이기 전의 goal 거부다. `ABORT`는 수락 후 실패이며,
`CANCELED`는 취소 전파가 완료된 상태다.

### 3.2 공통 결과와 에러

모든 스킬·공정 액션 result의 첫 필드는 `ResultBase base`다. 현재 표준 코드는
다음뿐이다.

| 코드 | 의미 |
|---|---|
| `E_INVALID_GOAL` | 필수값, 범위 또는 티칭 경계가 잘못됨 |
| `E_SAFETY_BLOCKED` | 안전 상태가 이동을 허용하지 않음 |
| `E_PRECOND_FAILED` | 전제조건 또는 요구 툴 불일치 |
| `E_TIMEOUT` | 동작이나 응답 대기 시간 초과 |
| `E_CANCELLED` | 사용자 또는 상위 액션 취소 |
| `E_COMM_LOST` | 컨트롤러나 하위 액션 서버 통신 실패 |
| `E_MOTION_FAILED` | TF, 도달성, DSR 이동 또는 자세 검증 실패 |
| `E_LATERAL_LIMIT` | 연마 진입 깊이가 티칭 경계의 기하 한계를 넘음 |
| `E_TOOL_MISMATCH` | 요구 툴과 현재 툴 불일치 |
| `E_GRIP_FAILED` | 그리퍼 명령 호출 실패. 실제 파지 검증 실패를 뜻하지 않음 |
| `E_OVERFORCE` | Probe 전체 힘 또는 옆힘이 지정 상한에 도달함 |
| `E_NO_BOUNDARY` | 접촉/비접촉 전환점이 부족해 경계를 만들 수 없음 |

### 3.3 안전 상태

`SafetyState`의 안전 입력은 E-Stop과 컨트롤러 통신뿐이다.

- `FAULT_ESTOP`: DSR `robot_state` 6 또는 7
- `FAULT_COMM_LOST`: 상태 조회 실패 또는 `heartbeat_timeout_ms` 초과
- 두 결함은 래치되며 물리 원인을 해소한 뒤 `/safety/reset`을 호출한다.
- `auto_reset`의 운용 기본값은 `false`다.
- `/safety/validate`는 `safe_to_move`와 `required_tool`만 검사한다.

## 4. A계층 스킬

### 4.1 `robot_skill_node`

#### `MoveTo`

`target_key`가 있으면 `targets.yaml`의 티칭 자세를 사용하고, 없으면 `target`을
`frame_id`에서 기준 프레임으로 변환한다. `linear`에 따라 선형 또는 관절 이동을
명령하고 최종 위치 오차를 반환한다.

#### `PickPlace`

```text
PICK:  티칭 위치 상공 -> 필요 시 그리퍼 개방 -> 하강 -> grip_width_mm 명령 -> 상승
PLACE: 티칭 위치 상공 -> 하강 -> 개방 명령 -> 상승
```

`already_holding=true`는 핀셋처럼 기존 툴을 유지한 채 물체만 집거나 놓을 때
완전 개방을 피한다. result에는 폭 측정이나 성공 판정 필드가 없다. `success`는
이동과 그리퍼 명령이 오류 없이 끝났다는 뜻이며, 실제 물체 보유 여부는 육안으로
확인한다.

#### `ContactPath`

- `reference_key`가 있으면 기존 상대 경로, 비어 있으면 Pose 전체를 절대 경로로 쓴다.
- `circular_via_indices`로 표시한 경유점·종료점 쌍은 `MoveC`, 나머지는 `MoveL`이다.
- `contact_offset_mm`으로 tool +Z 방향 접촉 깊이를 미세 조정한다.
- 첫 waypoint에서 tool -Z 방향으로 20 mm 떨어진 위치까지 `MoveJX`로 접근한 뒤
  첫 접촉점에는 `MoveL`로 진입한다.
- `allowed_polygon`이 3점 이상이면 다각형 밖 waypoint를 발견하는 즉시 중단한다.
- 결과는 `path_error_mm`, 완료 패스 수, 누락 인덱스와 중단 사유다.
- 종료 시 작업면에서 멀어지는 검증된 툴 축 방향으로 이탈한다.

#### `LateralContact`

- 연마용 티칭 좌표 배열을 선형 이동으로 순회한다.
- `approach_vector`는 경로 이탈 방향을 정하는 단위 방향이며 0벡터는 거부한다.
- 첫 waypoint는 낮은 접근 속도, 이후 waypoint는 `feed_speed_mms`를 사용한다.
- 종료 시 `approach_vector` 반대 방향으로 `retreat_mm`만큼 후퇴한다.
- 경계와 진입 깊이는 이 스킬이 측정하지 않는다. `sanding_node`가 티칭 경계로
  경로를 만들고 실행 전에 한계를 검사한다.

#### `ProbePoint`

- 운영자가 새 Probe 도구 장착을 확인한 경우에만 goal을 수락한다.
- `base_frame_id`의 `search_start`에서 지정 축으로 탐색하며, 같은 X/Y·자세의
  base +Z 공중 위치에서 먼저 동일한 이동 프로파일을 측정한다.
- 실제 압축력이 `공중 최대 압축력 + comparison_margin_n`을 연속
  `confirm_samples`회 넘으면 접촉이다. 최대 깊이까지 넘지 않으면 정상적인
  비접촉 표본이다.
- `stiffness_depth_mm`이 0보다 크면 접촉 뒤 그 거리만큼 같은 이동 안에서 더
  진행해 압축력 증가율(`stiffness_n_per_mm`)을 기록한다. 이는 안전 판단이 아닌
  손톱·더미손 재질 분류용 측정값이다.
- 전체 힘 또는 옆힘 상한에 도달하면 즉시 정지하고 `E_OVERFORCE`로 중단한다.
- 이동 완료 뒤 실제 Pose가 요청 목표에 도달했는지 확인한다. 두산이 이동을 시작하지
  않은 경우를 정상 비접촉 표본으로 처리하지 않는다.
- 접촉 위치, 이동거리, 공중/실제 최대 압축력, 분리값, 옆힘과 강성값을 반환한다.
- 별도 TCP와 실기 신뢰성이 확정되지 않아 전체 세션에는 연결하지 않는다.

### 4.2 `tool_manager`

1. 랙 이동 전에 중립 TCP로 전환한다.
2. 현재 툴이 있으면 해당 슬롯에 `PickPlace(place)`한다.
3. 새 툴 슬롯에서 `PickPlace(pick)`한다.
4. `tcp_<tool>`을 활성화하고 `/tool/status`를 갱신한다.

`ToolState.grip_width_mm`는 마지막 명령값이며 실측값이 아니다. 툴 교체 성공 후
운영자가 실제 파지와 랙 안착을 확인해야 한다. UV 툴 반납 실패 시 HOME으로
이동하지 말고 정지 상태에서 수동 개입을 요청한다.

## 5. B계층 공정

### 5.1 티칭 경계와 `nail_perception`

연마·경화·스톤은 `static_frames.yaml`의 `nail_local_frame`과 `nail_region`을
사용한다. 브러싱·코팅은 `taught_surfaces.yaml`에 툴별로 저장한 여섯 절대 Pose를
사용한다. 생산 공정은 센서 입력을 받지 않는다.

경계는 실제 손톱보다 보수적으로 티칭하고, 지그나 손 위치가 바뀌면 다시
티칭한다. 잘못된 티칭값을 런타임에 찾아내는 장치는 없다.

독립 `scan_boundary_node`는 공중 Pose 네 점으로 정한 사각형 범위를 3mm 거친
격자로 탐색한다. 손톱 내부 기준점과 더미손 기준점의 반복 강성 중앙값을 먼저
측정하고, 각 격자점을 더 가까운 재질로 분류한다. 손톱 기준점에 연결된 후보만
남긴 뒤 전환 구간 주변을 1mm 정밀 격자로 다시 측정한다. 최종 경계는 볼록껍질이
아닌 fine 격자 전환선을 직접 연결한 다각형이다. 각 격자점은 공중 보정을 다시
수행하므로 느리다. `manual_probe_tool_confirmed=true`와 힘/이동거리 상한이
필수이며, 안전 상태는 `ValidatePrecondition`을 통해 `safety_monitor`가 판정한다.
결과는 실기 검증 전 생산 공정에서 쓰지 않는다.

### 5.2 `sanding_node`

- 티칭 경계에서 진입점과 반대편 경계까지의 거리를 구하고
  `travel_limit_margin_mm`을 뺀 기하 한계를 계산한다.
- 경계가 무효하거나 계산 한계가 0 이하이면 이동 전에 실패한다.
- `engagement_depth_mm`이 계산 한계를 넘으면 이동 전에 실패한다.
- 경계의 진입측 호를 `engagement_depth_mm`만큼 안쪽으로 이동시킨 티칭 경로를
  만들고 `LateralContact`에 전달한다.
- `max_travel_mm`은 현재 구현에서 적용한 기하 진입 깊이이며 센서 측정값이 아니다.

### 5.3 `brushing_node`

브러시 전용 `P1~P6`에서 `P1-P2-P3`, `P4-P5-P6` 곡선과 두 직선 경계를 만든다.
그 사이를 `path_pitch_mm` 간격으로 왕복하며, 짧고 유효한 원호는 `MoveC`, 나머지는
`MoveL`로 `ContactPath`에 전달한다. `configured=false`이면 goal을 거부한다.
경계 밖 waypoint는 스킬의 `allowed_polygon` 검사로 차단된다. 성공은 지정 경로
완료만 의미하며 분진 제거 상태를 측정하지 않는다.

### 5.4 `coating_node`

코터 전용 `P1~P6` 경계를 만들고 `boundary_offset_mm`만큼 안쪽의 곡면 왕복
경로를 `ContactPath`에 전달한다. 원호 검증과 `configured` 게이트는 브러시와 같다.
`contact_offset_mm` 기본값은 0 mm이며 실제 더미에서 소량 조정한다.
`coverage_ratio`는 좌표 경로 기반 추정치이며 실제
도포 상태나 두께 측정값이 아니다.

### 5.5 `curing_node`

티칭 경계 안의 지점을 `MoveTo`로 순회하며 각 지점에서 정해진 시간 동안
체류한다. 안전 실패나 취소 시 조사 영역 밖으로 물리적으로 이탈한다. UV 툴을
안전하게 반납하지 못하면 HOME 복귀를 시도하지 않는다.

### 5.6 `stone_node`

`PickPlace`로 스톤을 집고 티칭된 위치로 이동해 위치 기반으로 내려놓는다.
`actual_position`은 명령 위치이며 측정 결과가 아니다. 부착 여부는 육안으로
확인한다.

## 6. C계층과 웹

`session_orchestrator`는 다음 상태를 발행한다.

```text
PRECHECK -> SAND -> BRUSH -> COAT -> CURE -> [STONE] -> FINISH
```

각 단계의 툴 교체와 작업 위치 이동을 포함하며 취소와 단계별 타임아웃을 하위
액션에 전파한다. `/process/status`와 `RunSession` feedback은 동일한
`ProcessState` 계약을 사용한다.
하위 액션 취소 후 결과는 `child_cancel_wait_s`(기본 10초)까지만 기다린다.

웹 브리지는 `/safety/status`, `/process/status`, `/session/run`,
`/safety/reset`만 노출한다. 웹은 저수준 로봇 명령이나 공정 판정을 소유하지
않는다.
